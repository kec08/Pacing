## 구현 요약

러닝 중 앱이 백그라운드로 전환되더라도 위치 추적과 음악 재생, 주변 러너 위치 브로드캐스트가 가능한 범위에서 계속 유지되도록 앱 설정과 실행 흐름을 보강했다.  
위치 추적은 백그라운드 위치 업데이트를 허용하도록 `LocationManager` 설정을 확장했고, 오디오는 앱 시작 시 `AVAudioSession`을 `playback` 카테고리로 구성해 재생 지속성을 높였다.

추가로 위치 브로드캐스트는 기존 5초 타이머 업로드만 의존하지 않도록 현재 위치가 갱신될 때마다 즉시 `refreshBroadcast`가 호출되도록 보완했다.  
러닝 화면과 종료 요약 화면의 통계 표시는 사용자 피드백에 맞춰 `페이스`, `평균 페이스`, `칼로리` 중심으로 문구를 정리했다.

## 구현된 기능 목록

- [x] `LocationManager`에 `allowsBackgroundLocationUpdates` 적용
- [x] `LocationManager`에 `showsBackgroundLocationIndicator` 적용
- [x] `authorizedWhenInUse` 상태에서 `Always` 권한 업그레이드 요청 보강
- [x] 앱 오디오 세션을 `AVAudioSession.playback`으로 설정
- [x] `UIBackgroundModes`에 `location`, `audio` 명시
- [x] 위치 업데이트 수신 시 Realtime DB 브로드캐스트 즉시 갱신
- [x] 러닝 중 오버레이에 `칼로리` 추가
- [x] 러닝 중 오버레이의 `랩 페이스` 문구를 `페이스`로 정리
- [x] 종료 요약 화면의 가운데 지표를 `평균 페이스`로 정리

## 계획서 대비 변경 사항

| 항목 | 계획 | 실제 구현 | 사유 |
|------|------|-----------|------|
| 백그라운드 위치 유지 | `LocationManager`와 설정 보강 | `allowsBackgroundLocationUpdates`, `showsBackgroundLocationIndicator`, 권한 업그레이드 처리 추가 | 러닝 지속 기록 안정성 확보 목적 |
| 브로드캐스트 유지 | 앱 생명주기 점검 | 타이머 유지 외에 위치 업데이트 시 즉시 `refreshBroadcast` 추가 | 백그라운드 타이머만으로는 위치 갱신 신뢰도가 떨어질 수 있기 때문 |
| 결과/러닝 카드 UI | 별도 신규 화면 없음 | 러닝 중 카드와 종료 요약 카드의 페이스/칼로리 문구 정리 추가 | 사용자 피드백 반영 |

## 알려진 제한사항

- 백그라운드 위치/오디오 동작은 설정상 보강했지만, 실제 안정성 평가는 실기기에서 화면 잠금/앱 전환 상태로 반드시 재확인해야 한다.
- `MainTabView.onDisappear`는 앱/씬 전환 방식에 따라 호출 타이밍이 달라질 수 있어, 브로드캐스트 종료 정책은 실기기 QA가 필요하다.
- 현재 빌드는 패키지 의존성까지 포함한 전체 컴파일 단계 진입은 확인했지만, 이번 턴에서는 `BUILD SUCCEEDED`까지 끝까지 확인하지 못했다.
