## 구현 요약

Realtime Database의 `activeRunners` 데이터에서 프로필 이미지 Base64를 분리하고, 필요한 주변 러너와 친구의 프로필만 Firestore에서 조회하도록 개선했다.

추가로 지도·주변 러너·같이 듣기 요청 및 세션 화면에서 프로필 이미지와 앨범 이미지를 안정적으로 표시하고, 같이 듣기 요청 상태와 시트 UI를 보완했다.

## 구현된 기능 목록

- [x] `activeRunners`에 `profileImageBase64`를 저장하지 않도록 분리
- [x] 1km 이내 러너 및 친구 대상 프로필 이미지 조회
- [x] 프로필 이미지 조회 실패 시 재시도 및 캐시 보완
- [x] 지도 핀과 주변 러너 목록 프로필 이미지 표시
- [x] 같이 듣기 요청·세션에서 참가자 프로필 이미지 표시
- [x] 같이 듣기 요청 화면에 곡 앨범 이미지와 곡 정보 표시
- [x] 같이 듣기 세션 앨범 이미지 Base64·URL·MusicKit fallback 적용
- [x] 요청 직후 `대기중`, 수락 후 `듣는 중` 상태 표시
- [x] 요청 버튼을 핑크색 채움 버튼으로 변경
- [x] 요청 수신 햅틱 강도 보완
- [x] 기본 가로형·확장 세로형 같이 듣기 시트 전환
- [x] 시트 확장 시 불필요한 상태 문구 제거 및 전환 애니메이션 적용

## 계획서 대비 변경 사항

| 항목 | 계획 | 실제 구현 | 사유 |
|------|------|-----------|------|
| 프로필 이미지 저장 | `activeRunners`에서 이미지 Base64 분리 | Realtime DB에는 위치·곡 정보만 저장하고 Firestore에서 필요한 대상만 조회 | Firebase 읽기/전송량 및 과금 부담 완화 |
| 조회 범위 | 1km 필터 후 프로필 조회 | 1km 이내 러너와 친구만 프로필 후보로 제한 | 지도 친구 표시와 주변 러너 필터 요구사항 동시 지원 |
| 같이 듣기 이미지 | 세션 참가자 이미지 표시 | 세션 필드, Firestore 재조회, UserDefaults fallback 적용 | 기존 세션 및 이미지 누락 데이터 호환 |
| 앨범 이미지 | 요청/세션에서 곡 정보 표시 | Base64·URL·현재 MusicKit 아트워크 순서로 fallback | 기기별 MusicKit/URL 제공 차이 대응 |
| 시트 UI | 기본 가로형 유지 | 기본 `.medium`은 가로형, `.large` 확장 시 세로형 | 사용자의 시트 동작 및 화면 구조 요구 반영 |
