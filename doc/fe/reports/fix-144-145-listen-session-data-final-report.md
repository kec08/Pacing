# #144·#145·#146 같이 듣기 안정화 최종 보고서

## 개요

같이 듣기 호스트·게스트의 재생 상태, 곡 전환, seek 동기화를 보완하고 프로필 이미지 누락 시 반복되는 Firestore 조회를 제한했습니다. 재생 장애가 발생했던 세션 경로는 `dev`의 검증된 호환 경로를 유지했습니다.

## 변경 사항

- `dev`와 동일한 기존 `listenSessions` 경로를 사용해 요청·수락·재생 상태 호환성 유지
- 호스트의 곡 전환·seek 이벤트를 즉시 브로드캐스트
- 게스트는 재생 이벤트 ID와 곡·위치 차이를 기준으로 필요한 경우에만 동기화
- MusicKit 큐가 외부 상태와 달라졌을 때 대상 곡 큐를 복구
- 재생 준비·재생 실패를 성공으로 처리하지 않고 재시도 가능한 상태로 보존
- 프로필 이미지 성공 캐시와 UID별 진행 중 Firestore 요청 공유 적용
- 이미지가 없는 결과는 10분 negative cache로 재조회 억제
- Slider의 마지막 seek 값 반영 지연으로 이전 위치가 전송되는 문제 보완
- seek 중 호스트 주기 브로드캐스트를 보류하고 종료 시 최종 위치만 전송

## 기술적 고려 사항

- `RealtimeDBService`의 기존 세션 계약과 외부 호출 시그니처를 유지
- `ListenTogetherViewModel`은 이벤트 중복 방지, 재생 실패 재시도, 프로필 캐시를 담당
- `RunningMusicViewModel`은 MusicKit 큐·재생·seek 상태를 담당
- 호스트 주기 브로드캐스트는 seek 입력과 경쟁하지 않도록 제어
- Firebase 프로필 조회는 성공·실패·진행 중 상태를 UID별로 공유
