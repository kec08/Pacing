## 구현 요약

러닝 측정이 백그라운드로 전환된 뒤에도 더 안정적으로 이어지도록 `LocationManager`의 앱 생명주기 대응과 위치 필터링 기준을 보강했다.  
또한 러닝 종료 요약 화면에서 상단 핵심 지표는 `평균 페이스`로 유지하고, 하단 km 단위 상세 섹션은 `km 평균 페이스`로 문구를 정리했다.

이번 작업 범위에서는 앱 아이콘 리소스는 수정하지 않았다.

## 구현된 기능 목록

- [x] 러닝 중 앱이 백그라운드/포그라운드로 전환될 때 위치 업데이트 설정 재적용
- [x] 백그라운드 위치 배치 수신 시 경로 기록용 정확도 허용 범위 완화
- [x] 백그라운드 위치 샘플이 거리/경로 계산으로 이어지도록 기존 흐름 유지 보강
- [x] 종료 요약 상단 지표 문구 `평균 페이스` 유지
- [x] 종료 요약 하단 섹션 문구를 `km 평균 페이스`로 변경
- [x] 앱 아이콘 변경 없이 현재 자산 유지

## 알려진 제한사항

- 현재 변경은 백그라운드 동작을 위한 코드 보강까지 완료된 상태이며, 실기기에서 `Always` 권한 허용 후 화면 잠금/앱 전환 상황까지는 아직 검증하지 못했다.
- 따라서 지금 시점에서는 `백그라운드에서 잘 작동된다`고 확정할 수 없고, `잘 동작하도록 코드 보강은 반영된 상태`로 보는 것이 정확하다.
- 현재 워크트리에는 앱 아이콘 관련 별도 변경 흔적이 보이지만, 이번 feat #41 구현 커밋에는 포함하지 않았다.
- 이 환경에서는 Xcode 전체 빌드 검증이 불가능해 컴파일 성공 여부를 최종 확인하지 못했다.

## 앱 아이콘 재발 방지 메모

- AppIcon 에셋은 `Pacing/Pacing/Assets.xcassets/AppIcon.appiconset/Contents.json`의 `filename`과 실제 파일명이 정확히 일치해야 한다.
- Xcode에서 `Any Appearance` 1024 슬롯 경고가 뜨면, 대부분 `Contents.json`이 존재하지 않는 파일명을 참조하는 경우다.
- 이번 충돌 사례처럼 브랜치마다 AppIcon 구조가 다를 수 있으므로, PR 전에는 `origin/dev` 기준 AppIcon 구성을 먼저 확인해야 한다.
- 현재 `dev` 기준 AppIcon은 `app-icon-single.png` 단일 1024 아이콘 구조를 사용한다. 이후 아이콘 교체 시에도 같은 구조를 유지하는 편이 안전하다.
