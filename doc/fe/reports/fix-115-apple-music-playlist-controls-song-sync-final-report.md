## 1. 구현 요약

Apple Music 플레이리스트 조회 제한을 제거하고, 홈·러닝·음악 탭이 공통 재생 큐와 현재 곡 상태를 사용하도록 정리했다. 미니 플레이어와 러닝 음악 시트에 재생·일시정지·이전·다음 곡 제어를 연결했으며, 러닝 시트의 인접 곡 슬라이드는 큐 재구성 없이 즉시 전환하도록 개선했다.

## 2. 변경 사항

### 플레이리스트 조회 및 성능

- 라이브러리 플레이리스트를 페이지 단위로 모두 조회한다.
- 플레이리스트 목록은 제목·커버 중심으로 먼저 표시하고, 수록곡·재생 준비는 사용자가 선택한 시점에 수행한다.
- 동기화 저장 상한은 별도로 유지해 Firestore 데이터량이 불필요하게 늘어나지 않도록 했다.

### 공통 재생 상태

- `ApplicationPlaybackContext`를 추가해 홈·러닝·음악 탭이 같은 재생 큐와 현재 곡 인덱스를 사용한다.
- 미니 플레이어의 재생/일시정지/이전/다음 동작을 ApplicationMusicPlayer에 연결했다.
- 수록곡 상세 목록은 공통 현재 곡 상태를 구독해 핑크 강조를 갱신한다.

### 러닝 음악 시트

- 재생 시간을 상태 동기화마다 0초로 초기화하던 경로를 제거했다.
- 이전/다음 곡 버튼을 ApplicationMusicPlayer 큐에 연결했다.
- 플레이리스트에서 선택한 곡의 앨범 커버를 우선 표시한다.
- 앨범 아트가 비어 있는 큐 엔트리는 카탈로그 ID와 제목·아티스트 검색으로 보강하도록 구현했다.
- 인접 곡 슬라이드 시 기존 큐를 재사용해 `prepareToPlay()` 재호출 지연을 제거했다.

## 4. 알려진 이슈 및 후속 작업

### 현재 재생 곡 앨범 커버 매핑

- **증상**: 러닝 음악 시트에서 일부 곡의 커버가 placeholder로 표시되거나 현재 재생 곡과 다른 커버로 나타날 수 있다.
- **추정 원인**: ApplicationMusicPlayer의 `Queue.Entry`가 곡별 아트워크·카탈로그 ID를 일관되게 제공하지 않으며, 라이브러리 곡과 카탈로그 곡의 식별자가 다를 수 있다.
- **후속 범위**: 재생 엔트리·라이브러리 `MPMediaItem`·카탈로그 검색 결과의 식별자를 단일 모델로 매핑하고, 곡 전환 중 이미지 요청 취소·캐시 키를 정합성 있게 관리한다.
- **상태**: 별도 GitHub 이슈 생성 후 다음 개발에서 처리.
