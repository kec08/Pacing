## 1. 목적 및 배경

현재 러닝 지도는 핀치 확대·축소와 드래그 입력을 받지만, 카메라 거리값을 `100m~3,000m`로 제한하고 조작 종료 후 재중앙 처리합니다. 이 때문에 사용자가 원하는 범위로 지도를 탐색하기 어렵습니다.

또한 러닝 중 위치 갱신마다 카메라를 다시 설정해 이동이 다소 끊기고, 사용자가 지도를 직접 살펴본 뒤에도 자연스럽게 추적을 중지·재개하기 어렵습니다. 실시간 러너와 친구 관계 데이터는 이미 존재하지만, 지도에는 친구 여부와 관계없이 주변 러너 핀이 표시됩니다.

본 작업은 지도 조작의 자유도를 높이고, 러닝 중인 친구 위치를 지도에 표시하며, 내 위치를 부드럽게 따라가는 카메라 경험을 제공합니다.

## 2. 사용자 시나리오

```
사용자가 러닝 탭에 진입하면
→ 지도에서 자유롭게 드래그·핀치 확대/축소한다
→ 직접 조작한 동안 자동 추적은 중지되고 선택한 지도 범위가 유지된다
→ 러닝을 시작하면 지도에 현재 러닝 중인 친구의 위치가 표시된다
→ 사용자가 내 위치 버튼을 누르면 현재 줌 레벨을 유지한 채 내 위치 추적이 재개된다
→ 위치가 갱신되면 카메라가 러너 위치를 자연스럽게 따라간다
```

## 3. 화면 구성

### 주요 화면

- 러닝 탭 지도: 지도 조작, 내 위치 핀, 러닝 경로, 친구 위치 핀을 표시한다.
- 지도 제어 버튼: 자동 추적 상태를 표시하고, 탭하면 현재 위치로 재중앙·추적 재개한다.

### UI 요소

- 지도 제스처: 드래그와 핀치 확대/축소를 MapKit 기본 동작 범위에서 허용한다.
- 내 위치 버튼: 자동 추적 중에는 메인 컬러로, 수동 탐색 중에는 기본 텍스트 컬러로 상태를 구분한다. 탭하면 카메라를 내 위치 기준 `1,000m` 거리로 맞추고 자동 추적을 재개한다.
- 내 위치 핀: 현재 사용자 위치를 표시한다.
- 친구 위치 핀: 현재 러닝 중이며 친구 관계인 사용자만 닉네임·프로필 이미지로 표시한다.
- 빈 상태: 러닝 중인 친구가 없을 때 별도 핀이나 경고를 표시하지 않고 지도를 유지한다.

## 4. 데이터 흐름

### 사용 데이터

- 위치: `LocationManager.currentLocation`
- 경로: `LocationManager.routeCoordinates`
- 실시간 러너: Realtime Database `activeRunners/{uid}`
- 친구 관계: Firestore `users/{uid}/friends/{friendUID}`

### 상태 관리

- `RunningView`
  - `cameraPosition`: MapKit 카메라 위치
  - `mapZoomDistance`: 사용자가 선택한 카메라 거리
  - `isFollowingUser`: 자동 추적 활성화 여부
  - 수동 제스처와 프로그램 카메라 이동을 구분해 추적 상태를 전환한다.
- `NearbyRunnerViewModel`
  - 현재 실시간 러너와 친구 ID를 기반으로 지도 표시용 친구 러너 목록을 제공한다.
  - 본인과 비친구 러너는 지도 표시 목록에서 제외한다.

## 8. 특이 사항 / 기술 검토

- MapKit 카메라는 시스템이 허용하는 범위 내에서만 확대·축소된다. 앱에서 임의의 최소·최대 거리로 다시 제한하지 않는다.
- 카메라를 위치 갱신마다 강하게 재설정하면 GPS 갱신 간격에 따라 끊김이 커질 수 있으므로, 자동 추적 중에만 짧은 애니메이션으로 중심 좌표를 갱신한다.
- 사용자의 수동 제스처 직후에는 프로그램 카메라 변경 이벤트를 구분해 자동 추적이 의도치 않게 다시 켜지지 않도록 한다.
- 친구 위치는 `activeRunners`에 브로드캐스트된 러너만 대상으로 한다. 위치를 공유하지 않거나 러닝을 종료한 친구는 지도에 표시하지 않는다.
- Realtime Database 보안 규칙은 이번 지도 UX 작업 범위에 포함하지 않는다. 친구 위치 노출 정책 변경이 필요하면 별도 보안 작업으로 분리한다.

## 9. 개발자 검토 포인트

- 친구 위치 핀은 현재 러닝 중인 친구 전체를 표시한다. 거리 제한을 적용하지 않는 방향으로 계획했다.
- 비친구의 위치는 지도에서 숨기며, 기존 주변 러너 시트의 필터 동작은 이번 작업에서 변경하지 않는다.
- GitHub 이슈 #67과 연결된 `feat/67-running-map-follow` 브랜치에서 개발한다.
