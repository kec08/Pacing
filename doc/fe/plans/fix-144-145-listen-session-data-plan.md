# #144·#145 같이 듣기 세션 데이터 및 프로필 조회 최적화 계획

## 목적

같이 듣기 세션의 1초 재생 위치 동기화가 프로필 이미지·앨범 커버와 함께 전체 스냅샷으로 반복 전송되는 구조를 개선하고, 프로필 이미지가 없는 세션 참가자에 대한 Firestore 반복 조회를 차단한다.

## 사용자 시나리오

- 호스트가 재생·일시정지·탐색·곡 전환을 하면 게스트의 재생 상태가 기존과 동일하게 동기화된다.
- 프로필 이미지가 있는 참가자는 세션 화면에 즉시 표시된다.
- 프로필 이미지가 없는 참가자도 재생 동기화가 중단되지 않으며, 같은 세션 갱신마다 Firestore를 재조회하지 않는다.
- 이전 형식으로 저장된 세션도 기존 사용자에게 오류 없이 열려야 한다.

## 구현 계획

### Task 1. 세션 데이터 경로 분리 (#144)

- 세션 생성 시 정적 메타데이터와 재생 상태를 `metadata`·`playback` 하위 노드로 분리한다.
- 프로필 이미지와 앨범 커버 Base64는 `playback` 갱신에서 제외한다.
- 호스트의 1초 갱신은 재생 위치·재생 상태·이벤트 식별자 등 필요한 값만 전송한다.
- 게스트는 메타데이터와 playback 하위 경로를 각각 구독하고 하나의 `ListenSession`으로 병합한다.
- `metadata`·`playback`이 없는 기존 세션은 legacy 루트 파싱으로 호환한다.

### Task 2. 프로필 이미지 조회 캐시 (#145)

- `ListenTogetherViewModel`에 UID별 성공 캐시를 둔다.
- 동일 UID의 조회가 진행 중이면 기존 Task 결과를 공유해 중복 요청을 막는다.
- 이미지가 없는 결과는 세션 수명 동안 재조회하지 않도록 negative cache를 적용한다.
- 세션 종료·새 세션 시작 시 캐시 범위를 정리하고, 이미지 보강 실패가 재생 동기화를 막지 않도록 한다.

### Task 3. 검증 및 문서화

- 기존 같이 듣기 요청·수락·종료·곡 전환·탐색·일시정지 흐름을 확인한다.
- `git diff --check`와 Debug iOS Simulator 빌드를 실행한다.
- Firebase 요청 경로와 프로필 fallback 동작을 코드 검토로 확인한다.
- 최종 보고서에 데이터 구조, 호환성, 검증 결과와 실기기 미검증 항목을 기록한다.

## 영향 범위 및 비범위

- 영향 범위: `RealtimeDBService`, `ListenTogetherViewModel`, `ListenSession` 모델 및 관련 문서.
- 기존 사용자 세션 데이터 마이그레이션은 이번 작업의 범위가 아니며 legacy 읽기 호환으로 대응한다.
- UI 디자인과 음악 재생 엔진 자체는 변경하지 않는다.

## 완료 기준

- [x] 재생 위치 갱신 시 프로필 이미지·앨범 커버 Base64가 전송되지 않는다.
- [x] 신규 구조에서 호스트·게스트 재생 동기화와 곡 전환 경로를 유지한다.
- [x] 프로필 이미지가 없는 UID는 세션 갱신마다 Firestore를 재조회하지 않는다.
- [x] 기존 세션 데이터도 정상 파싱된다.
- [x] 빌드 및 정적 검증이 통과한다.
