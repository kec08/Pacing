# 친구 프로필 접근 및 친구 요청 수락 오류 수정 계획서

## 1. 목적 및 배경

친구 탭에서 추천·검색 사용자의 프로필을 열면, 아직 친구 관계가 아닌데도 친구 전용 러닝 기록과 최근 음악을 함께 요청합니다. Firestore 규칙이 이를 거부하면 공개 프로필까지 실패한 것처럼 `친구 프로필 오류` 경고가 표시됩니다.

또한 받은 친구 요청 수락은 Cloud Function으로 상호 친구 문서를 생성하는 구조입니다. 호출 실패 시 앱은 원인과 무관하게 동일한 실패 문구만 표시하여 실제 수락 실패를 진단하거나 성공 상태를 검증하기 어렵습니다.

## 2. 사용자 시나리오

```
사용자가 추천/검색 결과에서 다른 사용자의 프로필에 진입하면
→ 공개 프로필은 항상 표시되고, 친구 전용 활동은 친구 관계일 때만 조회한다
→ 친구 요청 수락 후 상호 친구 관계가 생성되고 목록과 버튼 상태가 즉시 갱신된다
→ 수락이 실패하면 실제 원인을 확인 가능한 오류 처리와 재시도 가능한 UI 상태를 제공한다
```

## 3. 화면 구성

### 주요 화면
- 친구 프로필: 공개 프로필은 유지하고, 비친구에게는 친구 전용 러닝·음악 영역을 빈 상태로 표시합니다.
- 받은 친구 요청: 수락 완료 시 요청 행을 제거하고 친구 목록을 최신 상태로 갱신합니다.

### UX 원칙
- 권한으로 예상 가능한 비친구 상태를 전체 화면 오류로 노출하지 않습니다.
- 수락 처리 중 중복 탭을 막고, 성공 여부는 서버 응답과 관계 재조회로 확인합니다.

## 4. 데이터 흐름

### 사용 데이터
- Firestore: `users/{uid}`, `users/{uid}/friends`, `runHistory`, `recentSongs`, `friendRequests`
- Callable Function: `acceptFriendRequest`

### 상태 관리
- `FriendProfileViewModel`: 관계를 먼저 확인한 뒤, 친구 전용 데이터 조회를 조건부로 수행합니다.
- `FriendsViewModel`: 수락 처리 중 상태를 관리하고, Callable 응답 및 새 친구 관계를 확인한 뒤 목록을 갱신합니다.
- `FirestoreService` 및 Cloud Function: 수락 처리의 입력·결과를 명확히 검증하고 상호 친구 문서를 원자적으로 작성합니다.

- [ ] 단위 테스트 및 빌드, 수동 QA 체크리스트를 수행하고 결과를 이슈·최종 보고서에 기록한다.

## 6. 완료 기준 (Acceptance Criteria)

- [ ] 비친구 프로필 진입 시 `친구 프로필 오류` 경고가 표시되지 않고 공개 정보·친구 추가 동작이 정상 표시된다.
- [ ] 친구 관계인 프로필은 러닝 통계·최근 러닝·최근 음악을 정상 로드한다.
- [ ] 요청 수락 시 양쪽 `friends` 문서가 생성되고 요청 상태가 `accepted`로 변경된다.
- [ ] 수락 성공 후 받은 요청 목록과 친구 목록이 갱신되며 실패 경고가 나타나지 않는다.
- [ ] 수락 실패 시 중복 처리나 잘못된 성공 상태 없이 사용자가 재시도할 수 있다.

## 8. 특이 사항 / 기술 검토

- Firestore 보안 규칙상 비친구의 `runHistory`·`recentSongs` 조회 거부는 정상 동작이며, 앱이 이를 요청하지 않도록 해야 합니다.
- Callable Function 변경은 iOS 코드만의 수정으로 해결되지 않으므로, 배포 가능한 Firebase CLI 환경 여부를 확인하고 함수 배포까지 검증합니다.
- 기존 작업 트리의 사용자 변경 파일은 이 작업의 커밋·스테이징 대상에서 제외합니다.
