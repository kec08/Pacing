## 1. 목적 및 배경

홈 탭이 데이터 조회 지연 또는 실패 상황에서 스켈레톤 로딩 상태를 계속 표시하는 문제를 해소한다.

노래 탭의 친구 플레이리스트 목록과 상세 화면에서 기존 공유 데이터에 앨범/플레이리스트 커버 URL이 없으면 기본 음표 플레이스홀더만 표시된다. 사용자가 공유한 플레이리스트의 대표 커버와 수록곡 앨범 커버를 안정적으로 표시해 콘텐츠 식별성과 완성도를 높인다.

### 확인된 현행 흐름

- `HomeViewModel`은 러닝 기록(Firestore)과 같이 듣기 세션(Realtime DB) 요청을 하나의 `isLoading` 상태로 묶어, 어느 한 요청이 끝나지 않으면 홈 전체 스켈레톤이 유지될 수 있다.
- `SongViewModel`은 커버가 전혀 없는 친구 플레이리스트에만 Apple Music 카탈로그 보강을 수행하며, 곡별 커버가 일부 누락된 경우 및 재조회 실패 시 대표·곡 커버 복구가 충분하지 않다.
- 공유 플레이리스트 동기화 시 보강한 커버 정보가 원본 Firestore 문서에 항상 갱신되는 구조는 아니다. 따라서 오래된 공유 데이터는 반복적으로 플레이스홀더가 보일 수 있다.

## 2. 사용자 시나리오

```
사용자가 홈 탭에 진입하면
→ 러닝 기록과 친구의 최근 재생 음악이 독립적으로 로드되고
→ 각 영역은 완료·빈 상태·오류 상태로 전환되어 무한 스켈레톤 없이 홈을 사용할 수 있다.

사용자가 노래 탭에서 친구 플레이리스트를 열면
→ 저장된 대표 커버를 먼저 표시하고, 누락된 경우 Apple Music 카탈로그 정보로 보강하며
→ 목록 카드와 상세 헤더·수록곡 행에 동일한 앨범/플레이리스트 커버가 표시된다.
```

## 3. 화면 구성 및 UX

### 홈 탭

- 이번 주 러닝, 최근 러닝, 친구가 최근에 들은 음악의 로딩 상태를 독립 관리한다.
- 기존 `같이 들은 러너` 섹션은 제거하고, 친구별 최근 재생 곡을 작은 가로 앨범 카드로 표시한다.
- 카드에는 앨범 커버, 곡명, 아티스트, 친구 닉네임을 표시해 노래 탭의 큰 플레이리스트 카드와 시각적으로 구분한다.
- 각 요청이 끝난 뒤에는 결과가 없어도 해당 섹션만 빈 상태로 전환한다.
- 데이터 요청 실패 시 무한 로딩 대신 섹션별 안내와 다시 시도 가능한 화면 흐름을 제공한다.
- 당겨서 새로고침은 모든 홈 데이터를 다시 요청한다.

### 노래 탭 / 친구 플레이리스트 상세

- 친구 플레이리스트 카드: 대표 커버 URL을 우선 표시한다.
- 상세 헤더: 대표 커버가 없으면 첫 번째 유효 수록곡 앨범 커버를 사용한다.
- 수록곡 행: 곡별 앨범 커버 URL을 사용한다.
- URL이 없거나 실제 이미지 요청이 실패한 경우에는 현재의 음표 플레이스홀더를 유지한다. 깨진 이미지나 빈 영역은 노출하지 않는다.

## 4. 데이터 흐름 및 설계

### 홈 데이터

| 영역 | 데이터 소스 | 상태 |
|---|---|---|
| 이번 주 러닝 / 최근 러닝 | `users/{uid}/runHistory` (Firestore) | 로딩·콘텐츠·빈 상태·오류 |
| 친구 최근 음악 | `users/{friendUID}/recentSongs` (Firestore) | 로딩·콘텐츠·빈 상태·오류 |

- ViewModel에 섹션별 로딩·오류 상태를 둔다. View는 상태 표현과 재시도 이벤트 전달만 담당한다.
- 요청 취소·화면 재진입·인증 사용자 부재의 경우에도 `defer` 또는 동등한 종료 경로로 로딩 상태를 반드시 해제한다.
- 친구 관계 컬렉션에서 친구 목록을 조회한 뒤, 각 친구의 최신 `recentSongs` 1건을 결합한다. 친구가 재생한 곡이 없으면 해당 친구는 홈 음악 카드에서 제외한다.

### 친구 플레이리스트 커버

| 우선순위 | 대표 커버 | 수록곡 커버 |
|---|---|---|
| 1 | Firestore의 `artworkURL` | Firestore의 track `artworkURL` |
| 2 | Apple Music 플레이리스트 artwork | Apple Music 카탈로그 검색 artwork |
| 3 | 첫 유효 수록곡 앨범 커버 | 기본 음표 플레이스홀더 |

- 친구 플레이리스트 로드 시 누락된 대표·수록곡 커버를 보강한다. 필요한 Apple Music 검색은 중복 호출을 피하고 기존 메모리 캐시를 활용한다.
- 친구의 공유 문서는 보안 규칙상 소유자만 수정할 수 있다. 따라서 친구 플레이리스트 조회에서는 보강 결과를 메모리 이미지 캐시에 유지하고, 커버 URL과 곡의 `songStoreID` 영속화는 소유자 플레이리스트 동기화에서 수행한다.
- 개별 곡 또는 개별 플레이리스트의 보강 실패는 전체 목록 로딩 실패로 취급하지 않는다.
- 이미지 로더는 유효하지 않은 URL, 네트워크 실패, HTTP 오류에서 플레이스홀더로 안전하게 귀결되도록 유지·검증한다.

## 8. 특이 사항 / 기술 검토

- MusicKit 카탈로그 검색 및 artwork URL 발급은 Apple Music 권한·네트워크 상태에 의존한다. 따라서 영속화 전에도 플레이스홀더 폴백을 유지한다.
- 라이브러리 `Artwork.url`은 `musicKit://` 전용 스킴을 반환할 수 있으며 일반 URLSession으로는 열 수 없다. 공유·표시용 URL은 HTTP(S) 카탈로그 artwork로 제한한다.
- Firestore 규칙을 검증한 결과 타인의 공유 문서 수정은 허용되지 않는다. 친구 조회 시 보강된 커버는 현재 화면과 이미지 캐시에만 사용하고, 원본 문서의 갱신은 소유자 동기화 시에만 수행한다.
- 현재 작업 트리에 `Pacing/Pacing.xcodeproj/project.pbxproj` 사용자 변경이 존재한다. 본 작업은 이 파일을 변경하지 않으며, 빌드 단계에서 충돌 여부만 확인한다.
- GitHub 이슈 #69 생성 및 `dev` 기준 브랜치 분기를 완료했다.
