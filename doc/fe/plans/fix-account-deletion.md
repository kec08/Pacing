# 계정 삭제 기능 개발 기획서

## 1. 개요

| 항목 | 내용 |
| --- | --- |
| 작업 목적 | App Store Guideline 5.1.1(v)에 맞춰 앱 안에서 사용자가 직접 계정을 영구 삭제할 수 있도록 지원한다. |
| 작업 유형 | 심사 대응 / 기능 보완 |
| 예정 브랜치 | `fix/<issue-number>-account-deletion` |
| 대상 화면 | 마이 프로필의 설정 영역, 회원탈퇴 확인 화면 |
| 디자인 기준 | 라이트 모드(화이트 배경) 기준. 회원탈퇴 진입 텍스트는 로그아웃 아래의 회색 텍스트로 노출한다. |

## 2. 사용자 흐름

1. 사용자가 **마이 > 설정** 화면으로 이동한다.
2. 기존 `로그아웃` 바로 아래에 회색 `회원탈퇴` 버튼을 표시한다.
3. `회원탈퇴`를 누르면 삭제 전 경고 얼럿을 표시한다.
   - 제목: `회원탈퇴`
   - 안내: `탈퇴 시 계정과 러닝 기록, 친구 관계, 같이 듣기 정보가 삭제되며 복구할 수 없습니다.`
   - 동작: `취소` / 파괴적 동작의 `계속`
4. `계속`을 누르면 회원탈퇴 확인 화면으로 이동한다.
5. 사용자가 `탈퇴하겠습니다.`를 정확히 입력하면 하단 `탈퇴하기` 버튼이 활성화된다.
6. `탈퇴하기`를 누르면 로그인 방식과 관계없이 서버에서 계정 및 관련 데이터를 영구 삭제한다.
7. 삭제 성공 시 로컬 로그인 상태를 정리하고 로그인 화면으로 이동한다.
8. 동일한 OAuth 계정으로 다시 로그인하면 삭제된 계정을 복원하지 않고, 새 계정의 프로필 설정 흐름을 시작한다.

> 탈퇴 후 재로그인 시 복구 가능하다는 문구나 유예 기간은 제공하지 않는다. 이 기능은 즉시 영구 삭제를 기준으로 한다.

## 3. 화면 및 UX 설계

### 3.1 설정 화면

- `로그아웃` 행 아래에 별도 행으로 `회원탈퇴`를 배치한다.
- 회원탈퇴 텍스트는 회색으로 표시하고, 오동작을 막기 위해 로그아웃과 충분한 여백을 둔다.
- 탭하면 즉시 삭제하지 않고, 확인 얼럿을 먼저 노출한다.

### 3.2 1차 확인 얼럿

- 계정 삭제가 되돌릴 수 없음을 명확히 알린다.
- `취소`는 현재 화면에 남는다.
- `계속`을 선택한 경우에만 상세 회원탈퇴 화면으로 전환한다.

### 3.3 회원탈퇴 확인 화면

- 화이트 배경과 Pacing의 기존 라이트 테마를 사용한다.
- 다음 삭제 범위를 짧은 목록으로 안내한다.
  - 프로필, 신체 정보, 러닝 기록 및 최근 음악 기록
  - 친구 관계, 친구 요청, 공유 플레이리스트 및 같이 듣기 세션 정보
  - 삭제된 데이터는 복구할 수 없음
- `탈퇴 후 3개월 이내 재로그인 시 복구` 관련 문구는 포함하지 않는다.
- 안내 문구 아래에 `탈퇴하겠습니다.` 입력 필드를 제공한다.
- 입력값이 정확히 일치할 때만 `탈퇴하기` 버튼을 활성화한다.
- 삭제 요청 중에는 진행 상태를 표시하고 중복 탭 및 뒤로가기를 방지한다.
- 실패 시 로그인 상태를 유지하고, 재시도 가능한 오류 메시지를 표시한다.

## 4. 기술 설계

### 4.1 앱 계층

| 계층 | 책임 |
| --- | --- |
| View | 설정의 회원탈퇴 진입, 얼럿, 확인 문구 입력 및 상태 표현 |
| ViewModel | 입력값 검증, 삭제 진행/실패 상태 관리, 성공 후 앱 인증 상태 갱신 |
| UseCase | 탈퇴 확인 문구 검증 및 계정 삭제 실행 |
| Repository | Firebase Callable Function 호출 추상화 |
| Cloud Function | 인증된 사용자 식별, 관련 데이터 정리, Firebase Auth 계정 삭제 |

### 4.2 서버 측 영구 삭제

클라이언트에서 일부 데이터만 지우면 다른 사용자 문서, 실시간 세션, Firebase Authentication 계정이 남을 수 있다. 따라서 인증된 사용자만 호출할 수 있는 Firebase Callable Function으로 삭제를 처리한다.

삭제 함수는 현재 로그인한 UID를 서버에서 검증한 뒤, 아래 순서로 처리한다.

1. 진행 중 러닝/같이 듣기 상태를 정리한다.
2. Firestore의 `users/{uid}` 문서와 하위 컬렉션을 재귀적으로 삭제한다.
3. 전역 친구 요청, 공유 플레이리스트, 다른 사용자의 친구 목록에 남은 해당 UID 참조를 삭제한다.
4. Realtime Database의 활성 러너, 수신 요청, 해당 사용자가 참여한 같이 듣기 세션을 삭제한다.
5. 모든 데이터 정리가 성공한 경우에만 Firebase Authentication의 사용자 계정을 삭제한다. 이메일/비밀번호 계정과 Apple·Google·Kakao·Naver OAuth 계정에 동일하게 적용한다.

삭제 중 오류가 발생하면 인증 계정을 먼저 삭제하지 않으며, 오류를 기록하고 앱에서 재시도할 수 있게 한다.

OAuth 제공업체의 원래 계정(Apple ID, Google 계정 등)은 삭제하지 않는다. Pacing에 연결된 Firebase Authentication 계정과 Pacing 서비스 데이터만 삭제한다. 이후 동일한 OAuth 계정으로 인증하면 Firebase에 새 사용자 UID가 생성되고, 기존 데이터와 연결되지 않은 신규 프로필 설정을 진행한다.

### 4.3 앱 삭제 완료 처리

- 서버 응답이 성공한 뒤에만 Firebase 로그인 세션, `AppState`, 로컬 사용자 기본값을 정리한다.
- 앱의 인증 루트를 로그인 화면으로 전환한다.
- 로컬 상태만 지운 뒤 서버 삭제에 실패하는 불일치가 발생하지 않도록 처리 순서를 보장한다.

## 5. 구현 작업 단위

1. 기존 설정 화면과 사용자 데이터 저장 구조를 재확인한다.
2. 계정 삭제 Repository / UseCase / ViewModel 인터페이스를 추가한다.
3. Firebase Callable Function에 서버 측 계정·연관 데이터 삭제 로직을 구현한다.
4. 설정 화면에 회색 `회원탈퇴` 진입 행과 1차 확인 얼럿을 추가한다.
5. 탈퇴 확인 화면, 확인 문구 입력 검증, 로딩·오류 상태를 구현한다.
6. 삭제 성공 시 로그아웃 및 로그인 화면 전환을 연결한다.
7. 단위 테스트와 테스트 계정을 이용한 실제 삭제 QA를 진행한다.

## 6. QA 계획 및 완료 기준

- `회원탈퇴`가 로그아웃 아래에 회색 텍스트로 표시된다.
- 1차 확인 얼럿에서 취소하면 계정 삭제 화면으로 이동하지 않는다.
- `탈퇴하겠습니다.`와 한 글자라도 다르면 탈퇴 버튼이 비활성화된다.
- 정확한 문구 입력 시에만 버튼이 활성화된다.
- 테스트 계정으로 탈퇴 후 로그인 화면으로 전환된다.
- Firestore 사용자 문서 및 하위 데이터, 친구 요청/친구 관계/공유 데이터가 남지 않는다.
- Realtime Database의 활성 러너 및 같이 듣기 관련 데이터가 남지 않는다.
- Firebase Authentication에서 삭제된 계정이 더 이상 존재하지 않는다.
- Apple·Google·Kakao·Naver 각각의 테스트 계정으로 탈퇴 후 같은 제공업체로 재로그인해도 오류 없이 신규 가입/프로필 설정으로 진입한다.
- 네트워크 또는 서버 오류 시 계정을 유지하고 오류를 안내한다.
- 실제 기기에서 가입 또는 데모 계정 로그인 → 회원탈퇴 진입 → 확인 문구 입력 → 삭제 완료 흐름을 화면 녹화한다.

## 7. App Store 제출 반영

- App Review Information의 Notes에 계정 삭제 경로를 기재한다.
- 실제 기기 화면 녹화본을 Notes에 첨부한다.
- 녹화에는 로그인, 마이 화면의 회원탈퇴 메뉴, 확인 문구 입력, 삭제 완료 후 로그인 화면 복귀까지 포함한다.

## 8. 검토 요청 사항

- 탈퇴 처리 후 데이터 및 계정은 즉시 영구 삭제되며 복구되지 않는 정책으로 진행한다.
- 회원탈퇴 버튼은 요청대로 회색 텍스트로 표시하되, 최종 삭제 동작은 실수를 막기 위해 확인 문구 입력과 파괴적 버튼을 함께 사용한다.
- 기획 승인 후 GitHub 이슈 생성, `fix/` 브랜치 분기, 기능 구현 순서로 진행한다.
