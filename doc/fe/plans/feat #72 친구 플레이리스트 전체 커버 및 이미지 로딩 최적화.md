## 1. 목적

친구 플레이리스트 상세에서 일부 수록곡만 앨범 커버가 표시되는 문제를 해결하고, 이미지와 Apple Music 카탈로그 조회의 대기 시간을 줄인다.

## 2. 원인

- 공유 데이터를 만들 때 초기 몇 곡의 커버만 보강하는 제한이 있다.
- 누락된 곡의 카탈로그 검색이 순차 실행되어, 곡 수가 많은 플레이리스트에서 로딩 시간이 누적된다.
- 현재 이미지 로더는 메모리 캐시만 사용하며, 같은 URL에 대한 동시 요청 병합·디스크 캐시·이미지 다운샘플링이 없다.

## 3. UX 및 데이터 흐름

| 화면 | 동작 |
|---|---|
| 친구 플레이리스트 목록 | Firestore의 대표 커버 또는 첫 유효 곡 커버를 즉시 표시한다. 전체 수록곡 검색을 기다리지 않는다. |
| 플레이리스트 상세 | 기존 커버를 즉시 표시한 뒤, 누락된 모든 수록곡을 제한된 동시성으로 카탈로그 보강한다. 실패한 개별 곡만 플레이스홀더를 유지한다. |
| 이미지 표시 | 메모리·디스크 캐시를 우선 사용하고, 같은 URL 요청은 하나의 다운로드 작업을 공유한다. 화면 크기에 맞게 다운샘플링한다. |

## 4. 기술 설계

### 카탈로그 커버 보강

- `songStoreID`가 있는 곡은 배치 카탈로그 요청으로 우선 해결한다.
- 식별자가 없거나 배치 조회에 실패한 곡은 최대 4개씩 병렬 검색한다.
- 상세 화면에서만 모든 누락 곡을 보강한다. 목록은 대표 커버 1개만 보강해 첫 화면을 지연시키지 않는다.
- 보강 실패는 전체 로딩 실패가 아니며, 성공한 결과만 화면 상태에 반영한다.

### 이미지 로딩

- HTTP(S) URL만 허용하고 `musicKit://` URL은 계속 차단한다.
- URL 단위 in-flight 작업을 공유해 셀 재사용·프리패치 중복 다운로드를 막는다.
- `URLCache` 디스크 캐시와 `NSCache` 메모리 캐시를 병행한다.
- ImageIO 썸네일 다운샘플링으로 표시 크기보다 과도하게 큰 이미지 디코딩을 줄인다.
- 프리패치는 제한된 동시성으로 실행하고 취소된 화면 작업의 결과는 반영하지 않는다.

### Kingfisher 검토

Kingfisher는 위 캐시·다운샘플링·프리패치 기능을 제공하지만 Apple Music 카탈로그 매칭 지연은 해결하지 않는다. 이번 범위에서는 기존 공용 로더를 개선해 의존성을 늘리지 않는다. 이후 앱 전반의 원격 이미지 수요가 확대되면 Kingfisher 도입을 별도 아키텍처 결정으로 검토한다.

## 6. 완료 기준

- [ ] 상세에 표시되는 모든 수록곡은 유효한 카탈로그 매칭이 가능할 때 앨범 커버를 표시한다.
- [ ] 단일 곡의 검색 실패가 나머지 곡의 커버 표시를 막지 않는다.
- [ ] 목록 첫 진입은 전체 수록곡 보강을 기다리지 않는다.
- [ ] 동일 URL은 화면 내에서 한 번만 다운로드한다.
- [ ] 앱 재실행 뒤에도 HTTP 캐시 정책이 허용하는 범위에서 디스크 캐시를 우선 사용한다.
- [ ] `musicKit://` URL을 URLSession으로 요청하지 않는다.
- [ ] Debug 빌드와 실제 기기 음악 탭 QA를 통과한다.

## 7. 위험 및 대응

- Apple Music 검색 결과가 없는 곡은 커버를 만들 수 없으므로 플레이스홀더를 유지한다.
- 동시 요청 수를 제한해 API 요청 폭주와 화면 정지 위험을 줄인다.
- 친구 공유 문서는 타인이 수정할 수 없으므로, 조회 중 보강된 결과는 메모리 상태와 캐시에만 반영한다.
