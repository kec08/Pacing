## 1. 목적 및 배경

다음 음악·지도 경험의 오류를 한 번에 정비한다.

- 홈의 **친구가 듣고 있는 음악** 카드에서 앨범 커버가 비어 보이는 문제를 해결한다.
- 러닝 지도 최초 진입 시 현재 위치를 과도하게 확대한 카메라 값을 소폭 축소한다.
- 추천 플레이리스트와 앨범의 **저장** 동작이 Apple Music 보관함 및 앱 저장 상태에 정확히 반영되는지 검증하고 실패 경로를 수정한다.
- 친구 플레이리스트는 첫 수록곡의 앨범 커버가 아닌, 친구가 Apple Music에서 설정한 **플레이리스트 대표 커버**를 표시한다.

## 2. 사전 확인 결과

| 영역 | 현재 구현 | 확인/수정 방향 |
|---|---|---|
| 친구 최근 음악 커버 | Firestore의 `artworkData` 또는 `artworkURL`을 표시하고, 둘 다 없을 때만 Apple Music 검색으로 보강한다. | 만료·잘못된 URL과 이미지 다운로드 실패도 보강 대상으로 처리하고, UI에 실패 후 대체 경로를 제공한다. |
| 지도 최초 카메라 | `RunningView`의 초기 `mapZoomDistance`가 `400m`이다. | 초기 위치 자동 중앙 정렬 거리만 소폭 넓힌다. 내 위치 버튼의 별도 포커스 동작은 유지한다. |
| 추천 플리/앨범 저장 | `MusicLibrary.shared.add` 호출 뒤 화면 상태를 갱신한다. 추천 플리는 Firestore 저장도 병행한다. | 실제 보관함 반영 여부를 재조회해 확인하고, Apple Music 권한·구독·카탈로그 식별자·오류 메시지를 분리한다. |
| 친구 플레이리스트 커버 | 동기화 시 `loadedPlaylist.artwork`를 저장하지만, 기존 문서·누락값·대체 경로의 우선순위가 명확히 보장되지 않는다. | 대표 커버를 단일 진실 원천으로 고정하고, 동기화 갱신 및 목록/상세 표시 우선순위를 검증한다. |

## 3. 사용자 시나리오

```text
사용자가 홈에서 친구의 최근 음악을 보면
→ 친구가 들은 곡의 앨범 커버가 즉시 표시되며
→ 원본 이미지가 없거나 불러오기에 실패해도 카탈로그 보강 또는 플레이스홀더로 일관되게 표시된다.

사용자가 러닝 탭에 처음 진입하면
→ 현재 위치가 이전보다 조금 넓은 지도 범위로 중앙에 표시되고
→ 확대/축소 및 내 위치 버튼은 기존처럼 동작한다.

사용자가 추천 플레이리스트 또는 앨범에서 저장을 누르면
→ Apple Music 보관함 반영 성공을 확인한 뒤 저장됨 상태가 표시되며
→ 실패 시 실제 원인에 맞는 재시도 가능한 안내를 받는다.

사용자가 친구 플레이리스트 목록/상세를 열면
→ 친구가 설정한 플레이리스트 대표 커버가 표시되고
→ 첫 수록곡 앨범 커버로 대체되지 않는다.
```

## 4. 설계 및 작업 범위

### A. 친구 최근 음악 앨범 커버 복구

- `FirestoreService`의 최근 음악 데이터와 업로드 시점의 `artworkURL`/`artworkData` 유효성을 추적한다.
- base64 이미지, 유효한 원격 URL, Apple Music 카탈로그 보강의 우선순위를 명시한다.
- URL이 존재하더라도 다운로드·디코딩에 실패하면, 해당 곡 제목/아티스트로 한 번 보강을 시도한다. 보강 실패는 카드 전체 실패가 아니며 기본 플레이스홀더를 표시한다.
- 홈과 친구 프로필에서 공통으로 사용하는 커버 표시 방식을 정리해 동일한 실패 처리와 접근성 레이블을 적용한다.
- 네트워크 상태 및 오래된 Firestore 문서에서도 재현·검증한다.

### B. 러닝 지도 최초 위치 줌 조정

- `RunningView`의 최초 위치 자동 중앙 정렬에 쓰는 기본 `mapZoomDistance`를 400m에서 약 500~600m 범위로 조정한다. 최종 값은 실기기에서 보행자·러닝 시작 화면 기준으로 확정한다.
- 내 위치 버튼의 명시적 포커스 거리와 러닝 중 추적 카메라 정책은 변경하지 않는다.
- 위치 권한 승인 직후, 앱 재진입, 수동 지도 이동 후 재중앙 정렬의 동작이 서로 영향을 주지 않는지 확인한다.

### C. 플레이리스트·앨범 저장 정합성

- 저장 대상별 동작을 분리해 검증한다.
  - 친구 공유 플레이리스트: 앱 내 Firestore 저장 상태
  - Apple Music 추천 플레이리스트: Apple Music 보관함 저장 + 앱 내 저장 상태
  - 최근 재생 앨범: Apple Music 보관함 저장
- `MusicLibrary.shared.add` 성공 후 `libraryAddedDate` 또는 보관함 조회를 통해 실제 저장 상태를 재검증하고, UI 상태는 검증 결과를 기준으로 갱신한다.
- 권한 미허용, 구독 미지원, 카탈로그/보관함 식별자 오류, 네트워크 실패를 구분해 사용자에게 안내한다.
- 중복 탭을 차단하고, 실패 후에는 버튼을 재시도 가능한 상태로 복구한다.

### D. 친구 플레이리스트 대표 커버 정합성

- 동기화 시 `Playlist.artwork`만 대표 커버 필드로 저장하고, 수록곡 앨범 커버를 대표 커버로 채우는 대체 로직은 제거하거나 차단한다.
- 기존 Firestore 문서에 대표 커버가 비어 있거나 과거 값인 경우, 소유자 동기화 시 최신 플레이리스트 대표 커버로 갱신한다.
- 목록·상세·저장 문서에서 `SharedPlaylistSummary.artworkURL`을 최우선으로 사용한다. 대표 커버가 없는 경우에는 임의의 첫 곡 커버가 아니라 디자인 시스템 플레이스홀더를 보여준다.
- 타인 문서는 클라이언트가 수정하지 않으며, 커버가 누락된 경우 소유자의 다음 동기화에서 회복되도록 한다.

## 9. 기술 제약 및 검토 필요 사항

- Apple Music의 보관함 저장은 사용자의 미디어 라이브러리 권한과 활성 구독 상태에 의존한다. 앱 코드 수정 후에도 해당 조건이 충족된 실기기 검증이 필요하다.
- 친구의 플레이리스트 대표 커버는 친구 기기에서 동기화된 Firestore 데이터가 원천이다. 타인 문서를 현 기기에서 임의로 변경하지 않는다.
- 기존 작업 트리에 `Pacing.xcodeproj/project.pbxproj`, `Pacing.entitlements` 변경이 존재한다. 해당 변경은 보존하고 본 수정과 분리한다.
