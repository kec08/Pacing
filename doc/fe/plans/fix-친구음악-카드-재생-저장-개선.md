# 친구 음악 카드·재생 상태·Apple Music 저장 수정 계획서

> **관련 이슈**: [#93](https://github.com/kec08/Pacing/issues/93)

## 1. 목적 및 배경

노래 탭의 `친구가 듣고 있는 음악` 카드가 최근에 들은 앨범 카드와 달리 흰색 컨테이너·그림자를 포함해 시각적 일관성이 깨진다. 또한 친구 플레이리스트 목록 조회와 대표 앨범 커버 보강이 친구별·플레이리스트별로 순차 실행되어 첫 노출이 지연될 수 있다.

친구/Apple Music 앨범·플레이리스트 상세에서 다른 항목을 재생한 뒤 `전체 재생`을 누르면 실제 첫 곡은 재생되지만 첫 번째 곡 행의 재생 표시가 갱신되지 않는 문제도 있다. 마지막으로 친구 플레이리스트의 `플레이리스트 저장`은 앱 내부 Firestore 저장만 수행하면서 `저장됨` 상태를 표시하므로, 사용자가 기대하는 Apple Music 보관함(내 플레이리스트)에는 추가되지 않는다.

이번 수정은 위 네 가지 문제를 최소 범위에서 해결하고, 성공한 저장 상태만 사용자에게 노출한다.

## 2. 사용자 시나리오

```
사용자가 노래 탭에 진입하면
→ 친구가 듣고 있는 음악 카드는 앨범 카드와 같은 카드 외곽 없이 커버·제목·닉네임만 표시되고
→ 친구 목록과 대표 커버가 가능한 즉시 나타난다.

사용자가 다른 앨범/플레이리스트 재생 후 친구 상세에서 전체 재생을 누르면
→ 첫 번째 곡이 재생되고 해당 곡 행의 파형·강조 표시가 즉시 나타나며
→ 실제 재생 곡 변경에도 표시가 동기화된다.

사용자가 친구 플레이리스트에서 플레이리스트 저장을 누르면
→ 재생 가능한 수록곡으로 Apple Music 보관함 플레이리스트가 생성되고
→ Apple Music 저장과 앱 내부 저장이 모두 성공한 경우에만 저장됨으로 바뀐다.
```

## 3. 화면 및 UX 정책

| 영역 | 변경 정책 |
|---|---|
| 친구가 듣고 있는 음악 | `FriendSharedPlaylistCard`의 흰색 배경, 외곽 패딩, 그림자를 제거한다. 최근 앨범과 동일하게 커버(188pt, 18pt radius)와 텍스트만 배치하고, 가로 간격·잘림 정책을 맞춘다. |
| 친구 음악 로딩 | Firestore 친구별 조회와 대표 커버 보강의 순차 대기를 제거한다. 화면에는 Firestore 결과를 먼저 게시하고, 누락된 대표 커버만 제한 병렬로 보강·갱신한다. 이미지 캐시/프리패치는 기존 공용 로더를 계속 사용한다. |
| 전체 재생 표시 | 재생 시작 직후 첫 번째 행을 낙관적으로 표시하되, `ApplicationMusicPlayer` 큐의 현재 항목 이벤트를 단일 소스로 다시 동기화한다. 다른 앨범에서 넘어온 이전 상태가 남지 않도록 매칭 실패·정지 상태를 명확히 초기화한다. |
| 친구 플레이리스트 저장 | Apple Music 권한·구독·재생 가능 곡을 확인한 뒤 새 라이브러리 플레이리스트를 생성한다. 생성 실패 또는 앱 내부 저장 실패 시 `저장됨`을 표시하지 않고 오류를 안내한다. 중복 클릭은 저장 중 차단한다. |

## 4. 기술 설계 및 영향 범위

### UI

- 대상: `Features/Share/View/SongView.swift`
- 친구 카드의 레이아웃을 `RecentAlbumCard`의 시각 규칙에 맞추되, 친구 닉네임 정보는 유지한다.
- 로딩 스켈레톤도 최종 카드 크기·외곽 스타일과 일치시킨다.

### 친구 목록·커버 로딩

- 대상: `Core/Firebase/FirestoreService.swift`, `Features/Share/ViewModel/SongViewModel.swift`
- `fetchFriendSharedPlaylists`의 친구별 `getDocuments()` 호출을 제한된 동시성으로 병렬화하고, 기존 정렬·친구당 최대 3개·전체 최대 12개 정책을 보존한다.
- `enrichFirstTrackArtwork`는 화면 게시를 막지 않도록 후속 작업으로 분리한다. `songStoreID`와 유효한 기존 커버를 우선 사용하고, 실제로 누락된 항목만 보강한다.
- 화면 이탈/새로고침 시 이전 요청 결과가 최신 목록을 덮어쓰지 않도록 load ID 또는 취소 가능 Task를 둔다.

### 전체 재생 상태

- 대상: `Features/Share/ViewModel/SharedPlaylistDetailViewModel.swift`, 필요 시 `Core/Music/AppleMusicRecommendationService.swift`
- 전체 재생 전 큐에 들어갈 첫 곡과 화면 `tracks`의 식별자를 연결하고, 큐 설정/재생 준비 중에도 이전 상세의 `playingTrackID`가 남지 않게 초기화한다.
- `ApplicationMusicPlayer.queue.currentEntry`의 title/subtitle 매칭이 실패하는 경우를 확인하고, 카탈로그 ID·제목/아티스트 정규화·재생 시작 곡 식별자 중 신뢰 가능한 값으로 첫 곡을 판별한다.
- 재생 상태 변경, 큐 변경, 정지, 다른 앨범으로 전환, 개별 곡 재생의 회귀를 함께 검증한다.

### Apple Music 플레이리스트 저장

- 대상: `SharedPlaylistDetailViewModel`, `AppleMusicRecommendationService`, 필요 시 `SharedPlaylistModels`
- 친구 공유 원본(`.shared`)은 현재 Firestore만 저장하므로, `MusicLibrary`의 라이브러리 플레이리스트 생성 API를 별도 서비스 메서드로 추상화한다.
- 공유 곡을 카탈로그 곡으로 해석한 결과 중 재생 가능한 곡만 넣어 새 플레이리스트를 생성한다. 이름은 친구 플레이리스트 제목을 사용하고, 필요 시 소유자명을 설명/작성자 정보로 저장한다.
- Apple Music에 생성된 라이브러리 항목의 식별자 또는 생성 완료 사실을 앱 저장 문서에 기록해, 재진입 시 Firestore의 과거 `saved` 값만으로 Apple Music 저장 성공을 오인하지 않도록 한다.
- 저장은 **Apple Music 생성 성공 → Firestore 저장 성공** 순서로 처리한다. 두 번째 단계가 실패하면 명확히 오류를 표시하고, 재시도/중복 생성 방지 정책은 Apple Music 생성 결과 식별자를 기준으로 정한다.
- Apple Music 권한 없음, 활성 구독 없음, 해석 가능한 수록곡 없음, 생성 API 오류에는 각각 저장 실패 상태와 사용자용 메시지를 제공한다.

## 6. 완료 기준 (Acceptance Criteria)

- [ ] 친구 음악 카드는 흰색 박스·그림자 없이 최근 앨범 카드와 같은 시각 구조로 표시된다.
- [ ] 친구가 8명인 경우에도 친구별 공유 플레이리스트 조회가 순차 대기하지 않으며, 대표 커버 보강이 목록의 최초 표시를 막지 않는다.
- [ ] 캐시가 없는 조건에서 노래 탭 진입 시 친구 음악 목록/대표 커버의 로딩 시간과 네트워크 요청 수를 변경 전과 비교해 기록한다.
- [ ] 다른 앨범 또는 플레이리스트를 재생한 뒤 전체 재생을 누르면 첫 곡의 행이 즉시 재생 상태로 표시된다.
- [ ] 다음 곡 전환, 일시정지, 정지, 개별 곡 선택 시 재생 표시가 실제 현재 곡과 일치한다.
- [ ] 친구 플레이리스트 저장 성공 후 Apple Music 앱의 보관함 > 플레이리스트에서 해당 플레이리스트와 수록곡을 확인할 수 있다.
- [ ] Apple Music 저장 또는 Firestore 저장에 실패하면 버튼이 `저장됨`으로 바뀌지 않고 원인을 안내한다.
- [ ] 동일 친구 플레이리스트의 중복 탭/재진입에서 중복 생성되지 않는다.
- [ ] Debug 빌드 성공 및 실제 Apple Music 계정이 있는 기기 QA를 통과한다.

## 7. QA 매트릭스

| 시나리오 | 기대 결과 |
|---|---|
| 친구 0명/친구 1명/친구 다수 | 빈 상태와 목록 정렬이 정상이며, 다수 친구도 순차 조회 지연이 없다. |
| 기존 커버 있음/누락/잘못된 URL | 유효 커버는 즉시 보이고, 누락 항목만 보강하며 실패는 플레이스홀더로 끝난다. |
| 앨범 A 재생 → 앨범 B 전체 재생 | B의 첫 곡만 재생 표시가 되고 A의 표시는 남지 않는다. |
| 전체 재생 → 자동 다음 곡/일시정지/정지 | 표시가 현재 재생 상태와 일치한다. |
| 친구 플레이리스트 저장 성공 | Apple Music 보관함과 앱 저장 상태가 모두 확인된다. |
| 권한 없음·구독 없음·곡 매칭 실패·네트워크 실패 | 저장 완료 오표시 없이 재시도 가능한 오류 메시지를 제공한다. |

## 9. 특이 사항 / 개발자 확인 필요

- Apple Music 라이브러리 플레이리스트 생성은 실제 구독 계정과 기기 권한에서만 최종 확인할 수 있다. 시뮬레이터에서는 UI·상태 전이 및 실패 처리까지 검증한다.
- Apple Music 생성은 외부 서비스 변경을 수반하므로, Firestore 저장 실패 뒤 생성된 플레이리스트를 자동 삭제하지 않는다. 대신 생성 식별자 기록과 재시도 정책을 구현 전 확정한다.
- 현재 작업 트리에 `Pacing.xcodeproj/project.pbxproj`, `Pacing.entitlements`의 사용자 변경사항이 있다. 본 작업에서는 해당 변경을 건드리거나 포함하지 않는다.
