## 1. 목적 및 배경

홈의 `최근 러닝`과 마이페이지의 `최근 활동` 카드는 현재 정보 표시만 가능하고 탭해도 상세 기록으로 이동하지 않는다.
러닝을 마친 사용자가 거리·시간·평균 페이스와 실제 이동 경로, km별 페이스를 한 화면에서 확인할 수 있도록 공통 활동 상세 화면을 제공한다.

기존 Pacing의 흰색 카드, 핑크 포인트 컬러, 둥근 모서리와 SF Symbol 사용 원칙을 유지하되, 제공된 레퍼런스의 정보 위계(대형 거리 → 핵심 지표 → 경로 → 구간별 페이스)를 반영한다.

## 2. 사용자 시나리오

```
사용자가 홈의 최근 러닝 카드 또는 마이페이지의 최근 활동 카드를 탭한다
→ 동일한 러닝 활동 상세 화면으로 이동한다
→ 날짜·거리·시간·평균 페이스·칼로리(추정)와 이동 경로를 확인한다
→ 구간별 페이스를 열어 1km 단위 페이스를 확인한다
→ 이전 화면으로 자연스럽게 돌아간다
```

## 3. 화면 구성

### 주요 화면
- 활동 상세: 대형 거리, 핵심 지표, MapKit 경로, `구간별 페이스` 진입 버튼
- 구간별 페이스: km, 해당 구간의 평균 페이스와 상대 막대 표시

### UI 요소
- 공통 카드 링크: 전체 카드가 최소 44pt 터치 영역을 갖고 chevron으로 이동 가능함을 표시
- 상세 헤더: 날짜·시작 시간, 러닝 제목, 시스템 뒤로가기
- 핵심 지표: 평균 페이스, 시간, 거리, 칼로리(현재 거리 기반 추정값)
- 지도: 저장된 좌표가 2개 이상이면 MapKit 폴리라인 및 시작/종료 마커 표시; 없으면 안내형 빈 상태
- 구간: 저장된 km 랩 페이스 우선 표시, 과거 데이터처럼 랩 정보가 없을 때는 평균 페이스 기반 안내를 표시

## 4. 데이터 흐름

### 사용 및 저장 데이터
- `RunRecord`에 `lapPaces`를 추가한다.
- `RunningViewModel.completedLapPaces`를 러닝 저장 시 전달하고 Firestore `runHistory` 문서에 `lapPaces` 배열로 저장한다.
- 기존 `routeCoordinates`는 그대로 재사용한다.
- 기존 Firestore 문서에 `lapPaces` 필드가 없어도 빈 배열로 읽어 상세 화면이 정상 동작하도록 호환한다.

### 상태 관리 및 책임
- `RunRecord`: 활동 상세 표시용 데이터 모델
- `FirestoreService`: 랩 페이스 직렬화/역직렬화
- `RunningViewModel`: 종료 시 확정된 km 랩 전달
- `RunActivityDetailView`: 화면 표현 및 경로 카메라 제어만 담당
- `RunSplitPaceView`: 구간 목록·막대 UI 표현만 담당
- 별도 ViewModel은 비동기 추가 조회가 없으므로 만들지 않고, View에는 비즈니스 계산을 두지 않도록 모델의 표시용 연산 프로퍼티/순수 헬퍼로 제한한다.

- [ ] 다크 모드, Dynamic Type, VoiceOver 레이블과 44pt 이상 탭 영역을 확인한다.

## 8. 특이 사항 / 기술 검토

- 실제 고도·심박·케이던스는 현재 수집·저장하지 않으므로 이번 범위에서 새 지표로 추가하지 않는다. 레퍼런스의 정보 밀도는 현재 보유한 거리·시간·페이스·경로로 재해석한다.
- 칼로리는 기존 러닝 종료 화면과 같은 거리 기반 추정 규칙을 사용하며, 의료·정확 측정값으로 표기하지 않는다.
- 위치 권한이나 네트워크가 없어도 저장된 경로의 렌더링은 가능하다. 지도 타일은 네트워크 상태에 따라 달라질 수 있다.
- GitHub 이슈·브랜치·개발은 본 계획 승인 후 진행한다.
