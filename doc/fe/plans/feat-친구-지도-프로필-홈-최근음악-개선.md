## 1. 목적 및 배경

지도에서 내 위치는 이미 프로필 UI로 식별할 수 있으므로 별도의 내 위치 빨간 핀을 제거한다. 주변 러너는 임시 아바타 대신 각 사용자의 실제 프로필 사진을 일관되게 표시한다.

홈의 친구 최근 음악은 친구별 1곡만 노출되고 탭해도 재생할 수 없으며, 앨범 이미지가 비는 경우가 있다. 최근 재생 곡을 여러 개 조회하고, 카드를 탭하면 Apple Music에서 즉시 재생하며, 원본 이미지가 없거나 로드 실패해도 대체 커버를 항상 표시한다.

## 2. 사용자 시나리오

```
사용자가 러닝 지도를 열면
→ 지도에는 러닝 중인 친구의 실제 프로필 사진 핀만 보이고 내 위치 빨간 핀은 보이지 않는다

사용자가 홈의 친구 최근 음악 영역을 보면
→ 친구별 최근 곡이 여러 장의 더 큰 카드로 노출된다
→ 카드를 탭하면 해당 곡이 Apple Music에서 재생된다
→ 이미지 데이터·URL이 없거나 로드 실패해도 기본 앨범 커버가 표시된다
```

## 3. 화면 구성

### 주요 화면

- 러닝 지도: 내 커스텀 핀을 제거하고 친구 핀만 유지한다.
- 홈 > 친구가 최근에 들은 음악: 더 큰 가로 스크롤 카드, 재생 가능한 버튼, 앨범 커버 폴백을 제공한다.

### UI 요소

- 친구 지도 핀: Realtime DB의 `profileImageBase64`를 우선 사용하고 없을 때만 이니셜 아바타로 대체한다.
- 친구 음악 카드: 앨범 커버(104pt), 친구명·곡명·아티스트, 재생 상태 피드백을 제공한다.
- 앨범 커버: 저장된 Base64 → 원격 URL → 음악 아이콘 기반 컬러 폴백 순서로 표시한다.

## 4. 데이터 흐름

### 사용 데이터

- Realtime DB `activeRunners/{uid}`: 친구 러너의 닉네임, 위치, 프로필 사진.
- Firestore `users/{uid}/recentSongs`: 친구별 최근 재생곡 목록.
- Firestore `users/{currentUID}/friends`: 친구 ID·닉네임 목록.
- MusicKit: 카드 탭 시 `songStoreID`로 곡을 조회해 재생한다.

### 상태 관리

- `NearbyRunnerViewModel`: 본인을 필터링한 친구 러너 목록을 지도에 공급한다.
- `HomeViewModel`: 친구별 최근 재생곡을 다건 조회해 재생 시각 기준으로 정렬한다.
- `FriendRecentMusicCard`: 로컬 재생 상태와 실패 메시지를 표시하되 데이터 조회 책임은 갖지 않는다.

## 6. 완료 기준 (Acceptance Criteria)

- [ ] 지도에 내 위치 커스텀 핀이 나타나지 않는다.
- [ ] 지도 친구 러너 핀은 해당 친구의 프로필 사진을 우선 표시한다.
- [ ] 홈에는 친구 최근 음악이 친구당 복수 곡으로 표시된다.
- [ ] 곡 카드 탭 시 유효한 `songStoreID` 곡이 재생된다.
- [ ] 앨범 커버 URL·데이터 누락 또는 로드 실패 시에도 빈 영역 없이 대체 이미지가 표시된다.
- [ ] 확대된 카드가 다크 모드·동적 글자 크기에서 정보가 잘리지 않는다.

## 7. 기술 검토

- 친구 음악 재생은 MusicKit 권한 및 Apple Music 구독 상태에 의존한다. 권한·구독·Store ID가 없으면 카드 내에 실패 사유를 표시한다.
- Firestore의 친구 문서에는 프로필 사진 사본이 있을 수 있다. 실시간 러너의 사진은 브로드캐스트에 이미 포함되어 있어 해당 값을 우선 사용한다.
- 한 화면의 데이터 요청 과다를 막기 위해 친구 수와 친구당 조회 수에 상한을 둔다.
- 빌드 QA: `xcodebuild -project Pacing/Pacing.xcodeproj -scheme Pacing -sdk iphonesimulator -configuration Debug build`를 Xcode 26 환경에서 통과했다. 실기기 Apple Music 재생·Firebase 데이터 확인은 최종 검토 단계에서 수행한다.
