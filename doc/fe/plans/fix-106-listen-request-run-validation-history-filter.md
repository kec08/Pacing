# 같이 듣기 요청·러닝 기록 정합성·최근 활동 월 필터 복구 계획서

## 1. 목적 및 배경

다음 네 가지 사용자 문제를 함께 수정한다.

1. 같이 듣기 수신 요청 배너가 발신자의 실제 프로필 이미지 대신 이니셜 폴백을 표시한다.
2. 다크 모드에서 요청 배너의 흰색 외곽선이 표면 대비와 어울리지 않는다.
3. 매우 짧은 거리 또는 비정상적으로 큰 페이스의 기록이 최근 활동과 평균 페이스를 왜곡한다.
4. 최근 활동 월별 필터는 PR #97에서 구현됐지만 `main`에만 병합되어 현재 기준 브랜치 `dev`에는 반영되지 않았다.

## 2. 현황 확인 결과

- 수신 요청 배너는 `ListenSession.hostProfileImageBase64`를 표시한다. 요청 생성 시 이 값은 `UserDefaults`의 캐시만 사용하므로, 캐시가 비어 있거나 오래된 경우 발신자 프로필이 요청 데이터에 포함되지 않는다.
- 배너는 `.regularMaterial` 위에 `Color.white.opacity(0.55)` 외곽선을 고정 적용한다. 다크 모드에서 불필요하게 밝은 윤곽이 생긴다.
- 러닝 저장은 현재 1분 이상이면 거리가 0에 가깝거나 페이스가 비정상적으로 커도 저장한다. 마이 통계는 저장된 기록의 `avgPace` 단순 평균을 사용하며, 친구 프로필은 전체 시간/거리 비율을 사용한다. 두 경로 모두 무효 기록의 영향을 받을 수 있다.
- 월별 필터 구현 커밋 `449b260`(PR #97)은 `origin/main`에는 포함되지만 `origin/dev`에는 포함되지 않는다. 현재 `MyView`는 여전히 최근 5개와 `더보기` 방식이다.

## 3. 사용자 시나리오

```
러너 A가 러너 B에게 같이 듣기 요청을 보내면
→ A의 최신 프로필 이미지가 요청 세션에 저장되고
→ B의 수신 배너에서 A의 실제 프로필 이미지가 표시된다.

사용자가 다크 모드에서 수신 배너를 보면
→ 흰색 테두리 없이 머티리얼 표면·그림자만으로 배너 경계를 인지한다.

사용자가 제자리에서 앱만 실행했거나 비정상 위치 기록으로 짧은 거리를 저장하면
→ 활동 카드와 상세 요약의 페이스는 `--'--\"`으로 표시되고
→ 해당 기록은 평균 페이스 산정에서 제외된다.

사용자가 마이 탭 최근 활동에 진입하면
→ 기록이 있는 월을 선택해 해당 월의 모든 기록을 최신순으로 확인한다.
```

## 4. 수정 설계

### 4.1 같이 듣기 요청 프로필·다크 모드 UI

- 요청 전 발신자 프로필 이미지를 Firestore에서 최신 조회하고, 성공 시 `UserDefaults` 캐시도 갱신한 뒤 `ListenSession.hostProfileImageBase64`에 기록한다.
- 네트워크 조회 실패 시 기존 캐시를 폴백으로 사용한다. 이미지가 실제로 없는 계정만 현재 이니셜 아바타를 표시한다.
- 수신 배너의 고정 흰색 `.stroke` 오버레이를 제거한다. 기존 머티리얼 배경·코너·그림자는 유지해 라이트/다크 모드 모두에서 자연스러운 깊이를 확보한다.

### 4.2 러닝 기록 유효성 정책

- 공통 판정 로직을 `RunRecord` 또는 러닝 도메인 전용 경량 유틸리티에 둬 저장, 표시, 통계가 같은 기준을 사용하게 한다.
- 기본 기준은 아래와 같이 적용한다. 실제 운동을 차단하지 않으면서 이미지의 0.00~0.01km 기록을 제외하는 보수적 기준이다.

| 항목 | 기준 | 처리 |
|---|---:|---|
| 최소 유효 거리 | 0.10km 미만 | 페이스 무효 (`--'--\"`), 평균 페이스 제외 |
| 최대 유효 페이스 | 30분/km 초과 | 페이스 무효 (`--'--\"`), 평균 페이스 제외 |
| 그 외 | 거리·시간·페이스가 유한한 양수 | 기존 표시·집계 |

- 이미 Firestore에 저장된 기록은 삭제하거나 덮어쓰지 않는다. 조회 시점에 유효성을 적용해 최근 활동, 마이 통계, 친구 프로필 통계, 상세·요약 페이스가 모두 동일하게 표시·집계되게 한다.
- 신규 저장 기록도 동일한 정규화 값을 저장한다. 1분 이상이어도 무효 페이스인 기록은 활동 이력 자체는 보존하되 `avgPace`는 0으로 저장하고 랩 페이스도 무효값을 제외한다.
- 평균 페이스는 단순 기록 평균이 아닌, 유효 기록의 `총 시간 ÷ 총 거리`로 계산한다. 유효 기록이 없으면 `--'--\"`을 표시한다.

### 4.3 최근 활동 월별 필터 이관

- PR #97의 월별 필터 변경을 현재 `dev` 코드와 충돌 없이 이관한다.
- 기록이 있는 `연도+월`만 최신순 칩으로 제공하고, 선택 월의 모든 기록을 최신순으로 표시한다.
- 전체 이력 기준 `더보기/접기` 상태와 버튼은 제거한다.
- 현재 날짜 이후의 기록은 목록에서 제외한다. 월 필터 적용 후에도 100개 조회 한도는 현행대로 유지한다.
- 월별 목록에도 4.2의 유효성 판정을 적용한다.

## 6. 완료 기준

- [ ] 최신 프로필 이미지가 있는 발신자의 같이 듣기 요청 수신 배너에 실제 이미지가 표시된다.
- [ ] 프로필 이미지 조회 실패에도 요청/수신 흐름이 중단되지 않고 캐시 또는 이니셜 폴백이 적용된다.
- [ ] 다크 모드 요청 배너에 흰색 외곽선이 표시되지 않는다.
- [ ] 0.10km 미만 또는 30분/km 초과 기록은 모든 화면에서 페이스가 `--'--\"`으로 표시된다.
- [ ] 무효 기록은 마이 탭·친구 프로필의 평균 페이스에 반영되지 않는다.
- [ ] 유효 기록 평균은 총 시간÷총 거리 기준으로 계산된다.
- [ ] 최근 활동은 기록이 있는 월별 필터로 표시되며 전체 이력 `더보기/접기`가 없다.
- [ ] 라이트/다크 모드, 프로필 이미지 유무, 무효·유효 기록 혼재 조건에서 QA를 통과한다.

## 7. 검증 계획

- 프로필 이미지가 있는 계정/없는 계정 각각에서 A→B 같이 듣기 요청 수신을 확인한다.
- 다크 모드와 라이트 모드에서 배너의 외곽선·텍스트 대비·수락/거절 터치 영역을 확인한다.
- `0km`, `0.01km·5분`, `0.09km`, `0.10km`, `30:00/km`, `30:01/km`, 정상 5~10분/km 기록으로 페이스 표시와 평균 집계를 확인한다.
- 과거 여러 달의 기록과 미래 날짜 기록을 포함해 월 칩 정렬, 선택 목록, `더보기` 미표시를 확인한다.
