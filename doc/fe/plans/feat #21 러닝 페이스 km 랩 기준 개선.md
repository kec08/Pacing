# feat #21 러닝 페이스 km 랩 기준 개선

> **상태**: 진행 예정
> **작성일**: 2026-07-10
> **관련 이슈**: #35 예정
> **브랜치**: `feat/35-running-pace-by-km` 예정

## 1. 목적 및 배경

현재 러닝 화면의 페이스는 위치 샘플이 들어올 때마다 즉시 계산되어 초 단위로 계속 흔들린다.
실제 러닝 중 사용자가 인지하기에는 값 변동이 너무 잦고, 1km 단위로 기록되는 러닝 앱의 랩 페이스 경험과도 차이가 있다.

이번 작업은 러닝 화면의 핵심 페이스 지표를 `1km 랩 기준 페이스`로 정리해, 사용자가 km 완료 시점마다 더 안정적으로 페이스를 확인할 수 있게 한다.
진행 중인 현재 구간은 별도 실시간 스파이크 계산 대신 누적 거리/시간을 기준으로 안정적인 보조 계산을 사용한다.

## 2. 사용자 시나리오

```
사용자가 러닝을 시작한다
→ 시간과 거리는 기존처럼 계속 누적된다
→ 페이스는 위치 샘플마다 급격히 바뀌지 않는다
→ 1km를 채우면 해당 1km 구간의 랩 페이스가 확정된다
→ 2km, 3km도 같은 방식으로 랩 기준 페이스가 갱신된다
→ 1km 미만 초반 구간에서는 전체 누적 기준의 안정적인 임시 페이스를 본다
```

## 3. 화면 구성

### 주요 화면
- 러닝 화면 상단 스탯 오버레이
- 러닝 종료 후 요약 화면에서 사용하는 평균 페이스 값

### UI 요소
- 거리: 기존과 동일
- 페이스: 1km 랩 기준 값 우선 표시
- 필요 시 초기 1km 이전에는 누적 평균 기반 페이스 fallback

## 4. 데이터 흐름

### 사용 데이터
- `LocationManager.currentLocation`
- `RunningViewModel.elapsedSeconds`
- `RunningViewModel.distance`

### 상태 관리
- `RunningViewModel`
  - 전체 누적 거리/시간
  - 현재 랩 시작 시점 거리/시간
  - 마지막 확정 랩 페이스
  - 현재 표시용 페이스

## 5. 작업 목록 (Tasks)

- [ ] Task 2: `RunningViewModel`에 1km 랩 기준 상태 추가
- [ ] Task 3: 거리 누적 시 1km 경계 통과 여부 계산
- [ ] Task 4: 1km 완주 시 해당 랩 페이스 확정 로직 구현
- [ ] Task 5: 1km 미만 구간 fallback 페이스 표시 규칙 정리
- [ ] Task 6: `pause/resume/reset` 시 랩 상태가 깨지지 않도록 보정
- [ ] Task 7: 러닝 화면 표시 문구와 계산값 정합성 확인
- [ ] Task 8: 러닝 종료 저장 평균 페이스가 기존 요구사항과 충돌 없는지 확인
- [ ] Task 9: 빌드 및 QA 포인트 정리

## 6. 완료 기준 (Acceptance Criteria)

- [ ] 러닝 중 페이스가 위치 샘플마다 급격히 출렁이지 않는다
- [ ] 1km를 돌파하면 해당 km 구간 페이스가 기준값으로 반영된다
- [ ] 2km 이상에서도 매 km 랩 기준으로 일관되게 갱신된다
- [ ] 일시정지 후 재개해도 랩 계산이 이어진다
- [ ] 리셋 후 이전 랩 상태가 남지 않는다
- [ ] 평균 페이스 저장 값은 기존 총 시간/총 거리 기준을 유지한다
- [ ] Debug 빌드가 성공한다

## 8. 특이 사항 / 기술 검토

- Nike Run Club과 유사한 경험을 만들려면 "매 샘플 순간 속도"보다 "구간 완료 기준 랩 페이스"가 더 적절하다.
- 현재 구조는 위치 샘플 간 거리/시간으로 `rawPace`를 만들고 최근 5개 평균을 내므로 GPS 오차에 민감하다.
- 1km 경계는 하나의 위치 업데이트에서 여러 경계를 넘는 경우까지 방어적으로 계산하는 편이 안전하다.
- 저장되는 `avgPace`는 기록 요약용이므로 기존처럼 전체 시간/거리 기준을 유지하는 것이 자연스럽다.
