# 같이 듣기 호스트·게스트 곡/지도/썸네일 정합성 수정 계획서

## 1. 목적

멀리 떨어진 사용자 간 같이 듣기 세션에서 호스트가 재생 중인 동일한 곡을 게스트가 재생하고, 지도와 같이 듣기 화면에도 현재 세션 곡과 썸네일이 일관되게 표시되도록 수정한다.

## 2. 현재 증상

- 호스트와 게스트에서 서로 다른 곡이 재생된다.
- 게스트 쪽에서 곡이 재생되지 않는다.
- 지도 핀의 같이 듣기 곡이 세션의 현재 곡이 아니라 이전에 공유된 곡으로 표시된다.
- 같이 듣기 화면의 썸네일이 현재 곡이 아니라 이전 곡의 썸네일로 남는다.
- 같이 듣기 시트의 대표 앨범 이미지가 비어 있거나 현재 세션 곡과 무관한 placeholder/이전 이미지로 표시된다.

## 3. 코드 점검으로 확인한 원인

1. `ListenTogetherViewModel.sendRequest`에서 요청을 보내는 사용자를 `isHost = false`로 설정하고, 요청 수락 메서드에서 수락한 사용자를 `isHost = true`로 설정해 호스트/게스트 역할이 반대로 지정된다.
2. 요청 생성 시 호스트의 현재 재생 곡이 아니라 주변 러너의 곡(`runner.songTitle`, `runner.artist`)을 세션 초기 곡으로 기록한다.
3. 요청 수락 시 게스트의 로컬 플레이어 곡을 세션 대표 곡으로 덮어쓴다. 이후 실제 호스트는 브로드캐스트하지 않고, 게스트는 호스트 곡을 동기화하지 않는 흐름이 된다.
4. 지도 핀은 `activeRunners`의 개별 `songTitle`/`artist`를 사용하므로, 활성 같이 듣기 세션의 공통 곡 상태와 분리되어 있다.
5. 게스트 음악 화면과 같이 듣기 시트는 세션 곡 정보와 로컬 플레이어 상태를 혼합해 표시하고, 썸네일은 `artworkData`·`artworkURL`·로컬 아트워크의 우선순위가 곡 전환 시 안정적으로 무효화되지 않는다. 현재 `listenArtwork`는 세션 이미지가 없으면 로컬 artwork로 fallback하지만, 세션 이미지 확보/식별자 갱신 경로가 없어 같이 듣기 대표 이미지가 placeholder 또는 이전 이미지로 남을 수 있다.
6. 수락 전/초기 세션에서 타임스탬프 단위가 로컬 초와 Firebase 서버 밀리초로 혼용될 가능성이 있어, 위치 보정 기준을 서버 timestamp 기준으로 통일한다.

## 4. 목표 동작 및 완료 기준

- 요청을 보내는 사용자가 항상 호스트이고, 요청을 수락한 사용자가 항상 게스트이다.
- 세션 생성 시 호스트의 현재 곡, 곡 식별자, 제목, 아티스트, 썸네일, 재생 위치와 재생 상태가 저장된다.
- 세션이 `active`가 되면 게스트는 세션의 곡 식별자를 기준으로 곡을 준비하고, 라이브러리 검색은 명확한 식별자 매칭이 불가능할 때만 fallback으로 사용한다.
- 호스트의 곡 전환/재생/일시정지/탐색 위치가 세션에 반영되고, 게스트는 동일한 이벤트를 중복 큐 생성 없이 적용한다.
- 지도에서 세션 참여자 두 명의 핀 카드가 활성 세션의 최신 곡/아티스트를 표시한다. 세션이 없을 때는 기존 `activeRunners` 정보를 사용한다.
- 같이 듣기 시트와 음악 화면의 곡명, 아티스트, 썸네일이 동일한 세션 스냅샷을 사용하며, 곡 전환 시 이전 썸네일이 재사용되지 않는다.
- 같이 듣기 시트 상단 대표 앨범 이미지가 현재 세션 곡의 artwork data 또는 artwork URL로 표시되고, 이미지가 없는 경우에만 해당 곡 기준의 안전한 placeholder를 표시한다.
- 게스트 기기에서 Apple Music 권한/보유 여부 등으로 재생할 수 없을 때 무한 로딩 없이 사용자에게 상태를 표시하고, 호스트/세션 정보 표시는 유지한다.
- 기존 일반 주변 러너 지도, 단독 재생, 세션 종료, 요청 거절 흐름이 깨지지 않는다.

## 5. 작업 계획

### Task 1. 세션 역할과 초기 스냅샷 정정

- 호스트가 자신의 `RunningMusicViewModel` 스냅샷을 기반으로 세션을 생성한다.
- 생성 직후 호스트는 `isHost = true`로 설정하고, 게스트는 수락 후 `isHost = false`로 설정한다.
- 수락 메서드는 게스트의 곡으로 세션을 덮어쓰지 않고, 호스트가 기록한 스냅샷을 기준으로 수락 상태만 변경한다.
- 서버 timestamp 및 재생 위치 보정 단위를 검증하고 호환 처리한다.

### Task 2. 호스트 브로드캐스트와 게스트 동기화 안정화

- 호스트의 곡 전환 감지 키를 곡 식별자/제목/아티스트 기준으로 정리한다.
- 게스트는 활성 세션의 이벤트 ID가 변경될 때만 큐를 재구성하고, 동일 곡에서는 위치/재생 상태만 보정한다.
- 동기화 실패, 권한 거부, 라이브러리 검색 실패 상태를 로그와 UI 상태로 구분한다.
- 세션 종료/화면 이탈 시 관찰자, 타이머, 진행 중인 동기화 작업을 정리한다.

### Task 3. 지도 세션 곡 표시 정합성 수정

- 활성 세션의 참여자 UID를 기준으로 지도 핀에 세션의 최신 곡 스냅샷을 주입한다.
- 일반 러너의 곡 정보와 세션 곡 정보의 우선순위를 명확히 하고, 세션 종료 시 즉시 일반 정보로 복귀한다.
- 지도 핀의 곡명/아티스트/음표 상태가 Firebase 갱신 후 stale 값으로 남지 않도록 식별 가능한 상태 갱신을 적용한다.
- 같이 듣기 참여 중인 친구 핀은 친구의 개인 재생곡보다 활성 세션의 최신 곡/아티스트를 우선 표시한다.

### Task 4. 썸네일 표시 및 캐시 무효화 수정

- 세션 곡 식별자와 썸네일을 하나의 표시 모델로 묶어 곡명과 이미지가 서로 다른 곡을 가리키지 않도록 한다.
- `artworkData`/`artworkURL`/로컬 artwork의 우선순위를 정리하고, 세션 곡 식별자 변경 시 SwiftUI 이미지 identity를 함께 변경한다.
- 호스트와 게스트 모두 현재 세션 곡의 썸네일을 표시하고, 이미지 로딩 실패 시 곡 변경 전 썸네일을 유지하지 않는다.
- 같이 듣기 시트 대표 이미지, 음악 화면, 지도 핀에서 동일한 세션 artwork 스냅샷을 사용한다.
- artwork data가 없는 게스트도 store ID/곡 메타데이터로 현재 곡 artwork를 보강 조회하고, 조회 결과를 현재 세션 곡 식별자와 함께 캐시한다.

### Task 5. 테스트 및 QA

- 역할 확인: 호스트 요청 → 게스트 수락 후 양쪽 역할 및 세션 상태 확인
- 재생 확인: 호스트 재생, 일시정지, 다음/이전 곡, 위치 이동을 게스트에서 확인
- 원격 확인: 서로 다른 네트워크/장소에서 동일 곡 및 재생 상태 확인
- 지도 확인: 두 사용자 핀에 현재 세션 곡과 아티스트가 표시되는지, 곡 전환 후 즉시 갱신되는지 확인
- 썸네일 확인: 최초 곡, 곡 전환, 이미지 로딩 지연/실패, 세션 종료 후 단독 곡 복귀 확인
- 같이 듣기 시트 확인: 호스트/게스트 양쪽에서 현재 곡의 대표 앨범 이미지 표시 및 곡 전환 후 이미지 교체 확인
- 기존 단독 재생·주변 러너·요청 거절/종료 회귀 확인
- `xcodebuild` 컴파일, 관련 단위 테스트 또는 테스트 가능한 순수 로직 검증, `git diff --check` 실행
