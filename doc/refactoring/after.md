# Refactor 117 After

측정일: 2026-08-22

## 변경 사항

- `AppDelegate`를 `final class`로 변경해 상속 가능성을 제거했다.
- 홈 주간 통계를 `lazy.filter` 기반으로 변경해 유효 기록 중간 배열을 제거했다.
- 경로 세그먼트와 내 기록 차트 결과를 `reserveCapacity` 후 직접 `append`하도록 변경했다.

## 측정 결과

동일한 입력·컴파일 옵션·반복 조건으로 측정했다.

| 경로 | Before | After | 개선율 |
| --- | ---: | ---: | ---: |
| 경로 세그먼트 생성 | 0.04631 ms | 0.04548 ms | 1.8% |
| 유효 러닝 통계 집계 | 0.36086 ms | 0.07327 ms | 79.7% |

개선율은 `(Before - After) / Before × 100`으로 계산했다. 모든 측정에서 checksum이 일치했다.

## 포트폴리오용 요약

기존 주간 통계 집계는 `filter` 중간 배열을 생성한 뒤 여러 번 순회했으며, 100,000개 기록 기준 평균 0.36086 ms가 걸렸다. `lazy` 평가로 중간 배열 생성을 제거한 결과 평균 0.07327 ms로 줄어 **약 79.7% 개선**됐다.

경로 세그먼트 생성은 결과 배열을 예약하고 직접 변경하도록 바꿨으나, 기본 세그먼트 수가 최대 28개라 개선 폭은 1.8%로 측정됐다. 이 수치는 프로세스 간 변동 범위에 가까우므로 큰 성능 개선으로 홍보하지 않는다.

Static Dispatch의 `final` 변경은 앱 시작·UI 경로에서 독립적인 호출 비용을 안정적으로 분리 측정하기 어려워 별도 퍼센트를 산출하지 않았다. 대신 상속 불가 의도를 코드에 명시해 컴파일러가 정적 디스패치를 선택할 수 있는 조건을 만들었다.
