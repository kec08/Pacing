# #185 Apple Watch 음악 재생 동기화 및 최근 재생 UI 개선 계획서

## 개요

Apple Watch 음악 화면에서 발생하는 앨범 아트 누락, 곡 전환 및 재생 상태 반영 지연, 최근 재생 목록의 UI 불일치를 개선한다. Watch와 iPhone 러닝 음악 시트는 동일한 재생 상태를 빠르게 표시해야 하며, 네트워크 지연이나 WatchConnectivity 메시지 순서 변경에도 최신 상태가 유지되어야 한다.

관련 이슈: [#185](https://github.com/kec08/Pacing/issues/185)

## 현황 분석

### 동기화 흐름

- Watch는 `PhoneMusicPlaybackRepository`를 통해 iPhone의 음악 스냅샷을 구독하고 명령을 전송한다.
- iPhone의 `RunningMusicViewModel`이 재생 엔진을 제어하고 `PhoneRunSyncPublisher`로 상태를 발행한다.
- 현재 Watch 명령은 단방향 전송이므로, Watch가 낙관적으로 갱신한 UI와 iPhone의 실제 상태가 늦게 일치한다.
- 스냅샷에는 `updatedAt`이 있으나 명령과 직접 연결되지 않아 빠른 연속 입력에서 과거 상태가 보일 여지가 있다.

### 앨범 아트

- 스냅샷은 WatchConnectivity application context 크기 제한을 고려해 최대 58 KB로 관리한다.
- 용량이 초과되면 최근 재생/플레이리스트 아트워크 데이터를 제거하는 폴백이 적용된다.
- 현재 곡의 메타데이터가 먼저 도착하고 앨범 아트가 나중에 보강될 수 있어, 전환 중 placeholder 또는 이전 이미지가 남을 수 있다.

### Watch UI

- 러닝 음악 탭의 플레이리스트 버튼은 상단 고정 오버레이로 배치되어 있다. 위치는 유지한다.
- 현재 재생 행에는 재생 중 상태를 나타내는 핑크색 볼륨 아이콘이 아직 없다.
- 최근 재생 목록은 최대 12개이며 각 행에 별도 재생 아이콘이 있다.

## 구현 계획

### 1. 명령과 최신 상태의 일관성 보장

- Watch 명령에 요청 식별자와 기준 상태 정보를 포함한다.
- iPhone은 명령 처리 직후 최신 재생 상태 스냅샷을 우선 발행한다.
- Watch는 요청보다 오래된 스냅샷을 무시하고, iPhone이 확정한 최신 상태만 화면에 반영한다.
- 재생/일시정지는 Watch에서 즉시 낙관적으로 토글한 뒤 확정 스냅샷으로 보정한다.

### 2. 곡 전환 및 앨범 아트 전송 개선

- 다음/이전/직접 재생 시 현재 곡의 제목, 아티스트, 아트워크 식별자를 하나의 최신 상태로 갱신한다.
- 현재 곡 앨범 아트를 우선 보존하고, 목록 아트워크는 별도 캐시·보강 경로로 처리해 용량 초과가 현재 아트 노출을 방해하지 않게 한다.
- 수신한 아트워크는 곡 식별자 기준으로 캐시하고, 이전 곡 데이터가 새 곡 화면에 남지 않게 한다.
- 아트워크 데이터가 아직 없으면 URL 기반 로드와 placeholder를 사용하되, 최신 곡의 보강 결과만 반영한다.

### 3. Watch 음악 화면 UX 개선

- 현재 재생 중인 플레이리스트 행의 trailing 영역에 핑크색 `speaker.wave.2.fill` 아이콘을 표시한다.
- 플레이리스트 버튼의 상단 고정 위치와 터치 영역은 유지한다.
- 목록 표시 전환에 짧은 opacity/scale 또는 이동 애니메이션을 적용하고, Reduce Motion에서는 애니메이션을 비활성화한다.
- 최근 재생 목록을 최대 10개로 제한한다.
- 최근 재생 행에서 별도 재생 아이콘을 제거하고, 플레이리스트 행과 같은 앨범 아트·제목·아티스트 구조를 사용한다.
- 최근 재생 행 탭은 해당 곡 재생 명령을 보내며, iPhone 러닝 음악 시트에도 현재 곡과 재생 상태가 즉시 갱신되게 한다.

### 4. 구조와 테스트

- 전송 모델 및 Repository는 동기화 메시지 전달·순서 보장을 담당한다.
- Watch ViewModel은 낙관적 UI 상태와 확정 스냅샷 병합을 담당한다.
- `RunningMusicViewModel`은 MusicKit 제어 후 iPhone/Watch 공통 상태를 발행한다.
- Watch Repository/ViewModel 테스트와 iPhone 재생 상태 발행 관련 테스트를 추가 또는 보완한다.

## 완료 기준

- Watch의 다음/이전/곡 선택 후 iPhone 러닝 음악 시트와 제목, 아티스트, 앨범 아트, 재생 상태가 일치한다.
- 빠른 연속 입력 및 지연된 메시지 수신 후에도 과거 상태가 최신 상태를 덮어쓰지 않는다.
- 현재 곡 앨범 아트가 안정적으로 표시되며, 새 곡으로 넘어갈 때 이전 아트가 남지 않는다.
- Watch 재생/일시정지 버튼 아이콘이 사용자 입력 직후 바뀌고 iPhone 실제 상태로 확정된다.
- 현재 재생 곡은 핑크색 볼륨 아이콘으로 구분된다.
- 최근 재생은 최대 10개이며, 별도 실행 아이콘 없이 행 전체 탭으로 재생된다.
- 플레이리스트 버튼 위치는 기존과 동일하며, 목록 진입/종료가 부드럽게 동작한다.

## 검증 계획

1. 관련 Watch Repository/ViewModel 및 iPhone 음악 ViewModel 단위 테스트 실행
2. Debug iOS Simulator 및 Watch Simulator 빌드 실행
3. `git diff --check` 실행
4. 실기기 QA
   - 재생, 일시정지, 다음, 이전 및 최근 재생 곡 선택
   - 빠른 다음/이전 연속 입력
   - iPhone과 Watch의 제목·아트워크·재생 아이콘 동시 확인
   - 연결 지연/아트워크 지연 상황에서 최신 곡 표시 확인
   - 빈 상태, 다크 모드, 다양한 Watch 화면 크기, Reduce Motion 확인
