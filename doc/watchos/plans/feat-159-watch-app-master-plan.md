## 1. 목적

iPhone Pacing 앱과 연결되는 Apple Watch 러닝 경험을 구축한다. 워치는 러닝 시작·진행·종료를 빠르게 제어하고, 음악·같이 듣기·월간 활동을 짧은 확인 흐름으로 제공한다.

Nike Run Club의 워치 경험처럼 큰 지표와 즉시 조작을 우선하되, 화면 구성과 시각 요소는 Pacing 브랜드로 구현한다.

## 2. 범위와 원칙

- 기본 진입 페이지는 **2번 러닝 탭**이다.
- 네 화면은 좌우 스와이프로 이동하고 현재 위치를 간결한 페이지 인디케이터로 표시한다.
- 러닝 중에는 한 손으로 읽을 수 있는 큰 시간·거리·페이스를 우선한다.
- iPhone과 Watch의 공통 데이터는 기존 Firebase와 WatchConnectivity를 사용한다.
- 별도 백엔드나 새 서버 API는 만들지 않는다.

## 3. 탭 구성

| 순서 | 화면 | 러닝 전 | 러닝 중 |
|---:|---|---|---|
| 1 | 음악 | 최근 재생 곡 | 현재 재생 곡 및 제어 |
| 2 | 러닝 | 중앙의 큰 러닝 시작 버튼 | 실시간 러닝 대시보드 |
| 3 | 같이 듣기 | 친구·주변 사용자에게 요청 | 세션·참여자 상태 |
| 4 | 활동 | 이번 달 거리·횟수·최근 기록 | 진행 중 기록의 요약 반영 |

### Phase 1 — 러닝 탭

#### 러닝 전

- 중앙 원형 시작 버튼
- 시작 전 권한·연결 상태 안내
- 목표 설정은 후속 확장 가능하도록 모델만 고려

#### 러닝 중

- 상단 대형 지표: 시간, 거리, 현재 페이스
- 상단 대형 지표를 탭해 표시 순서·항목을 변경
- 하단 3개 보조 지표: 거리, 페이스, 심박수/칼로리
- 일시정지·재개·종료 제어

#### 기술 범위

- `HKWorkoutSession`, `HKLiveWorkoutBuilder`
- Watch 위치 측정과 거리·페이스 계산
- View / ViewModel / UseCase / Repository 책임 분리

### Phase 2 — 음악 탭

- 러닝 전: 최근 재생 곡 목록
- 러닝 중: 현재 곡, 앨범 아트, 재생/일시정지/다음 곡
- iPhone MusicKit 상태를 WatchConnectivity로 전달하는 흐름부터 구현

### Phase 3 — 같이 듣기 탭

- 친구·주변 사용자 목록과 요청 보내기
- 요청 수락·거절, 참여자·세션 상태 표현
- 실제 세션·음악 동기화는 기존 iPhone Firebase 로직을 재사용
- Watch는 요청·상태 확인·간단한 제어를 담당

### Phase 4 — 활동 탭

- 이번 달 누적 거리
- 이번 달 러닝 횟수
- 최근 러닝 거리·날짜·페이스
- 빈 상태·동기화 실패 상태

## 5. 데이터 및 연동

| 대상 | 책임 |
|---|---|
| HealthKit | 워치 운동 세션, 심박수, 운동 저장 |
| Core Location | 워치 위치·거리·페이스 측정 |
| WatchConnectivity | iPhone ↔ Watch UI 상태·음악·같이 듣기 요청 전달 |
| Firebase | 기존 Pacing 사용자·러닝 기록·같이 듣기 데이터 저장 및 조회 |

Firebase 컬렉션이나 Realtime Database 경로가 현재 기능으로 충분하면 변경하지 않는다. 새 필드 또는 경로가 필요한 경우에만 `doc/shared/`에 호환성·비용 영향을 기록한다.

## 6. 핵심 설계 결정

### 워치 단독 러닝 측정

권장안은 iPhone 없이도 러닝을 시작할 수 있는 워치 단독 운동 세션이다. iPhone은 상세 기록·음악·친구 기능의 보조 기기로 연결한다.

| 선택지 | 장점 | 고려 사항 |
|---|---|---|
| 워치 단독 측정 — 권장 | iPhone 없이 러닝 가능 | HealthKit·위치 권한 및 배터리 QA 필요 |
| iPhone 측정 전달 | 초기 구현 단순 | iPhone 미소지 러닝 불가 |
