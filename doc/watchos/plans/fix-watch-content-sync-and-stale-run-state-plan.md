# 워치 콘텐츠 동기화 및 잔류 운동 상태 방지 계획서

## 목적

워치 앱을 다시 열었을 때 아이폰 앱을 먼저 실행해야만 러닝 기록이 보이는 문제를 해결한다. 한 번 동기화한 러닝 기록과 최근 재생 음악은 워치에 보관하고, 새 데이터가 동기화되면 최신 값으로 갱신한다.

동시에 WatchConnectivity의 `applicationContext`에 남아 있는 이전 운동 상태가 워치 UI를 러닝 정지 화면으로 전환하는 문제를 막는다.

## 원인

- 워치 수신기의 러닝 기록·음악 스냅샷은 메모리에만 유지되어 워치 앱 프로세스가 재생성되면 사라진다.
- 운동 상태 스냅샷도 `applicationContext`에서 수신되며, 이전 `paused` 스냅샷이 현재 운동이 없어도 워치의 러닝 탭과 정지 화면을 열 수 있다.
- 워치가 열릴 때 아이폰에 러닝 기록 갱신을 요청하는 경로가 없어, 캐시가 비어 있으면 아이폰 앱의 다음 동기화를 기다린다.

## 작업 범위

1. 워치 콘텐츠 캐시
   - 러닝 기록 스냅샷과 음악 재생 스냅샷을 워치 `UserDefaults`에 저장한다.
   - 수신기 초기화 시 캐시를 먼저 복원하여 네트워크·아이폰 앱 상태와 무관하게 기존 콘텐츠를 표시한다.
   - 새 스냅샷은 갱신 시각을 비교해 최신 값만 화면 및 캐시에 반영한다.

2. 워치 열기 시 콘텐츠 갱신
   - 워치 수신기 활성화와 기록 화면 진입 시 아이폰에 러닝 기록 갱신을 요청한다.
   - 즉시 메시지 전송이 불가능하면 백그라운드 전달 큐를 사용한다.
   - 아이폰 동기화 발행기가 요청을 받으면 저장소에서 최신 러닝 기록을 조회해 워치 컨텍스트로 발행한다.
   - 음악 갱신 요청도 연결 상태가 아닐 때 백그라운드 전달 큐로 보완한다.

3. 잔류 운동 상태 차단
   - 영구 콘텐츠와 달리 `phoneRun` 운동 상태는 `applicationContext` 복원값으로 워치 UI를 전환하지 않는다.
   - 실시간 메시지·사용자 정보로 받은 운동 상태만 현재 세션에 적용한다.
   - 워치 루트 화면은 운동 상태가 실제로 적용된 경우에만 러닝 탭으로 이동한다.

4. 검증
   - 워치 대상 빌드 및 관련 단위 테스트를 실행한다.
   - 캐시 복원, 새 기록 갱신, 잔류 정지 상태 미표시, 연결 불가 시 갱신 요청 전달을 실기기 QA 항목으로 정리한다.

## 제외 범위

- 러닝 상세 화면의 레이아웃·표시 형식 변경
- 아이폰 러닝 세션의 측정 로직 변경
- 자동 PR 생성 및 병합 (실기기 테스트 및 최종 검토 후 진행)
