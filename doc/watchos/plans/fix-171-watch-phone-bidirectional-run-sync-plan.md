# fix #171 iPhone·Watch 양방향 러닝 제어 및 종료 동기화 계획서

> **작성일**: 2026-09-21
> **관련 이슈**: [#171](https://github.com/kec08/Pacing/issues/171)
> **기준 브랜치**: `dev`

## 문제 정의

현재 #169 작업으로 iPhone에서 러닝을 시작하면 Watch 앱이 실행되고, iPhone의 러닝 시간·거리·페이스 상태가 Watch에 전달됩니다. 그러나 제어 방향이 iPhone에서 Watch로만 열려 있습니다.

- Watch에서 러닝을 시작해도 iPhone 러닝이 시작되지 않음
- Watch에서 일시정지·재개·정리/종료해도 iPhone 러닝 상태가 변경되지 않음
- 양쪽 앱이 각각 별도의 운동 세션과 화면 상태를 가질 수 있음

## 목표

iPhone과 Apple Watch가 하나의 러닝 세션을 공유하고, 어느 기기에서든 시작·일시정지·재개·종료를 수행하면 상대 기기의 운동 세션과 화면 상태가 같은 순서로 반영되도록 합니다.

## 구현 계획

### 1. 공통 명령 및 상태 모델 정의

- `start`, `pause`, `resume`, `finish` 명령 모델 정의
- 명령 식별자, 발생 시각, 송신 기기, 세션 식별자를 포함해 중복 처리 방지
- 기존 iPhone 스냅샷과 Watch 수신 모델을 양방향 메시지 구조로 확장

### 2. iPhone 수신 경로 구현

- WatchConnectivity로 Watch 명령 수신
- iPhone `RunningViewModel`의 시작·일시정지·재개·종료 로직을 명령 처리 경로에서 재사용
- iPhone에서 이미 처리한 명령은 식별자로 무시해 재전송·복구 상황에서도 중복 운동 세션이 생성되지 않도록 처리

### 3. Watch 송신 경로 구현

- Watch 러닝 화면의 시작·일시정지·재개·정리/종료 액션을 명령 발행으로 연결
- Watch 단독 시작 시 iPhone에도 시작 명령을 보내고, iPhone의 세션 시작 결과를 기준 상태로 수렴
- 연결 불가 시 최신 명령을 보류하고 재연결 후 전달할 수 있는지 기존 WatchConnectivity 정책과 함께 검토

### 4. 종료 및 운동 세션 정리

- 한쪽에서 종료되면 양쪽 ViewModel의 상태를 `ended`로 수렴
- HealthKit 세션 종료, 타이머 중지, WatchConnectivity 구독 해제, 화면 상태 정리 순서를 명확히 분리
- 정리 버튼과 종료 버튼의 의미가 다른 경우 현재 UI 동작을 확인해 동일 세션 종료 정책으로 매핑

### 5. 검증 및 실기기 QA

- iPhone 시작 → Watch 실행·러닝 화면·상태 반영
- Watch 시작 → iPhone 러닝 화면·운동 세션 시작
- 양방향 일시정지·재개
- iPhone 종료 → Watch 종료
- Watch 정리/종료 → iPhone 종료
- 연결 지연·앱이 백그라운드인 상태·중복 이벤트·권한 거부 상태

## 기술적 고려 사항

- MVVM 책임을 유지하고, View에는 명령 호출만 두며 동기화·중복 제거·상태 수렴은 별도 Core/Repository 계층에서 처리합니다.
- `sendMessage`는 즉시 제어 명령에 사용하고, `updateApplicationContext`는 최신 러닝 상태 복구에 사용합니다.
- 메시지 순서가 뒤집히거나 동일 명령이 재전송되는 상황을 고려해 세션 ID와 명령 ID를 검증합니다.
- 기존 iPhone 시작 → Watch 실행 흐름과 Watch 단독 러닝 기능을 회귀시키지 않습니다.
