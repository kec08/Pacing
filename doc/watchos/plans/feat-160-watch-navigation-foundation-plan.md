## 목표

Nike Run Club Watch 앱과 유사하게 좌우 스와이프로 이동하는 4개 탭의 기본 골격을 만든다. 앱을 열면 두 번째 탭인 **러닝** 화면이 기본으로 표시되며, 하단 지표를 눌러 원하는 탭으로도 이동할 수 있어야 한다.

| 순서 | 탭 | 이번 단계에서 제공하는 내용 |
| --- | --- | --- |
| 1 | 음악 | 최근 재생 음악을 위한 빈 상태 UI |
| 2 | 러닝 | 앱의 기본 탭, 러닝 시작 CTA와 준비 안내 |
| 3 | 같이 듣기 | 주변 사용자/친구 초대 기능을 위한 빈 상태 UI |
| 4 | 활동 | 이번 달 거리·횟수 및 최근 러닝을 위한 요약 UI |

## 설계

### 화면 구조

- `TabView(selection:)`의 페이지 스타일을 사용한다.
- `WatchTab` 열거형이 탭의 순서, 제목, 아이콘, 접근성 문구를 단일하게 관리한다.
- `WatchAppViewModel`이 선택된 탭과 러닝 화면의 공통 상태를 보유한다.
- 화면은 현재 단계에서는 표시 전용 목업이며, 이후 기능별 View/ViewModel로 분리할 수 있는 이름을 사용한다.

### 기본 상태

- 기본 선택 탭: `running` (두 번째 페이지)
- 러닝 상태: `idle`
- 러닝 시작 버튼은 실제 운동 세션을 생성하지 않고, 다음 단계에서 연결된다는 안내만 표시한다.

## 제외 범위

- HealthKit 권한 및 `HKWorkoutSession` 기반 실시간 러닝 측정
- GPS 거리·페이스·시간·칼로리 표시와 백그라운드 동작
- MusicKit/Apple Music 최근 재생곡 및 현재 재생곡 연동
- WatchConnectivity, Firebase, 같이 듣기 실시간 요청/수락
- 실제 월간 러닝 기록 조회

## 검증 기준

- 앱 시작 시 러닝 탭이 선택된다.
- 스와이프 및 하단 탭 지표 탭으로 네 화면을 이동할 수 있다.
- 실제 운동·음악·네트워크 요청은 실행되지 않는다.
- 다크 모드 Watch 화면에서 텍스트와 조작 영역이 읽기 쉽다.

## 검증 결과

- `xcrun --sdk watchsimulator swiftc -typecheck` 통과
- `git diff --check` 통과
- 전체 `xcodebuild`는 기존 iOS 패키지 의존성의 네트워크 다운로드가 필요한데, 실행 환경의 DNS 제한으로 완료하지 못했다.
