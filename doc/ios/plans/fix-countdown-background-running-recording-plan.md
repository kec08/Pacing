## 문제 및 원인

러닝 시작 후 `3 → 2 → 1` 카운트다운이 끝나기 전에 앱을 홈 화면으로 보내거나 화면을 잠그면, 카운트다운 완료 시 호출돼야 할 `RunningViewModel.start()`가 실행되지 않아 러닝 세션과 위치 기록이 시작되지 않을 수 있다.

기존 구현은 `RunningView`의 UI `Task`가 3초를 기다린 뒤에만 위치 추적을 시작했다. 카운트다운 중 앱이 백그라운드가 되면 iOS가 이 작업을 중지할 수 있다. 기존 #57의 백그라운드 GPS 설정은 이미 `dev`에 반영되어 있으며, 이번 문제는 그 설정이 활성화되기 전의 시작 전환 문제다.

## 설계

| 계층 | 책임 | 변경 |
|---|---|---|
| `RunningView` | 카운트다운 표시와 시작 입력 | View 소유 `Task` 제거, ViewModel 상태 표시 |
| `RunningViewModel` | 카운트다운 수명과 단일 시작 전환 | 카운트다운 시작·취소·완료를 관리 |
| Background task | 백그라운드 전환 중 3초 작업 완료 지원 | `beginBackgroundTask`로 제한된 실행 시간 요청, 완료·취소·만료에서 종료 |
| `LocationManager` | 실행 중 러닝의 GPS 수집 | 기존 #57 백그라운드 위치 처리 유지 |

## iOS 제한

앱 전환과 화면 잠금은 지원 범위다. 앱 전환 화면에서 사용자가 강제 종료했거나 iOS가 프로세스를 종료한 경우의 자동 시작은 iOS 정책상 보장할 수 없다.
