# 러닝 고도 상승·페이스 정합성 및 지표 탭 순환 개선 계획서

## 1. 작업 목적

러닝 중 및 러닝 종료 후 표시되는 고도 상승 값이 GPS 고도 노이즈로 과장되지 않도록 계산 기준을 보완하고, 페이스 계산이 실제보다 빠르게 보이지 않는지 계산 파이프라인을 재검증한다. 또한 러닝 중 지표를 현재의 위치별 2개 값 순환 방식에서 전체 지표 목록을 순서대로 탐색하는 방식으로 개선한다.

## 2. 현재 확인된 문제

### 2.1 고도 상승

- `RunMetricsCalculator.elevationGain`이 `verticalAccuracy <= 30m` 샘플을 모두 허용한다.
- 연속 샘플의 양의 고도 변화가 `2m` 이상이면 누적하므로, 실제 상승이 아닌 GPS 오차가 여러 번 누적될 수 있다.
- 위치 샘플은 러닝 경로에 저장되지만 고도 전용 필터·스무딩·급격한 변화 검증은 없다.

### 2.2 페이스

- 거리 누적은 `RunningPacePolicy.isValidRunningSegment`를 통과한 위치 구간만 사용한다.
- 페이스 표시값은 1km 랩이 확정되면 랩 페이스, 그 전에는 누적 시간/거리 평균을 사용한다.
- 저장 평균 페이스는 전체 경과 시간/누적 거리 기준이므로, 일시정지·GPS 배치 업데이트·유효 구간 제외가 표시 기준과 일관되는지 테스트가 필요하다.
- 속도 상한 및 정확도 조건이 실제 러닝 데이터에서 빠른 값으로 치우치지 않는지 경계값과 합성 위치 샘플로 검증한다.

### 2.3 러닝 지표 탭

- 현재 좌·중·우 위치가 각각 2개 지표만 순환한다.
- 따라서 지표가 위치에 고정되어 있고, 6개 지표를 전체 순서로 탐색할 수 없다.
- 대상 지표 순서는 `km → 고도 상승 → 페이스 → BPM → 케이던스 → 칼로리`로 통일한다. 화면의 3개 슬롯에는 현재 선택 상태를 유지하되, 어느 슬롯을 눌러도 다음 미표시 지표가 해당 슬롯에 배치되도록 설계한다.

## 3. 구현 방향

### Task 1. 계산 정책과 테스트 기준 고정

- 고도 상승과 페이스의 단위, 유효 데이터, 일시정지 처리 기준을 계산 정책으로 명시한다.
- 고도는 유효 수직 정확도, 최소 변화량, 급격한 단일 샘플 이상치 및 연속 노이즈 누적을 검증할 수 있는 순수 함수 테스트를 추가한다.
- 페이스는 정지 GPS 흔들림, 정상 러닝, 비정상적으로 빠른 구간, 일시정지 후 재개, 1km 랩 경계 케이스를 테스트한다.

### Task 2. 고도 상승 계산 보정

- 고도 샘플을 수직 정확도와 timestamp 기준으로 먼저 필터링한다.
- 단일 샘플의 큰 상승을 그대로 더하지 않고, 인접 샘플 또는 짧은 구간의 고도 변화가 지속적으로 확인되는 경우만 누적하도록 검토한다.
- 허용 가능한 최대 상승 변화량과 노이즈 제거 기준은 `CLLocation`의 정확도보다 보수적인 값으로 설정하고, 실제 등산 수준의 상승을 과도하게 제거하지 않도록 테스트로 경계를 정한다.
- 유효 샘플이 부족하면 임의의 0 또는 추정값 대신 기존 표시 정책에 맞는 `nil`/초기 표시를 유지한다.
- 러닝 중 표시와 종료 후 저장값이 동일한 계산 함수를 사용하도록 유지한다.

### Task 3. 페이스 계산 재검증 및 보정

- 거리 누적에 사용되는 위치 구간과 페이스에 사용되는 시간 기준이 동일한지 확인한다.
- 유효하지 않은 GPS 구간을 시간에는 포함할지 여부를 명확히 하고, 일시정지 시간은 제외하는 현재 상태와 충돌하지 않는지 검증한다.
- 비현실적인 속도 구간을 제외한 뒤에도 평균 페이스가 빠르게 치우치는 원인이 있으면 속도 상한·최소 이동 거리·정확도 조건을 조정한다.
- 평균 페이스와 1km 랩 페이스의 반올림·표시 경계를 공통 포맷 정책으로 정리한다.

### Task 4. 전체 지표 순서 기반 탭 UI 개선

- `RunningMetric` 모델 또는 이에 준하는 단일 지표 목록을 도입해 표시 순서를 한 곳에서 관리한다.
- 3개 슬롯은 현재 화면에 표시되는 지표 ID를 보유하고, 슬롯 탭 시 전체 순서에서 다음 지표를 선택한다.
- 이미 다른 슬롯에 표시 중인 지표는 건너뛰어 중복 표시를 방지한다.
- 예시: 현재 `km / 페이스 / 칼로리`에서 세 번째 슬롯을 탭하면 다음 순서의 `고도 상승`이 세 번째 슬롯에 표시되고, 이후 어느 슬롯을 탭하더라도 남은 순서인 `BPM → 케이던스`를 이어서 표시한다.
- 접근성 라벨·탭 힌트·애니메이션은 새 순서와 일치하도록 수정한다.

### Task 5. QA 및 회귀 검증

- 단위 테스트와 프로젝트 테스트 타깃을 실행한다.
- 시뮬레이터에서 러닝 시작·일시정지·재개·종료 흐름과 지표 탭 순서를 확인한다.
- 실기기에서 GPS 품질이 다른 환경의 고도 상승 및 페이스를 확인한다.
- Apple Watch/HealthKit 심박수나 Core Motion 케이던스가 없는 경우에도 지표 순환이 깨지지 않고 `--` 정책을 유지하는지 확인한다.
- 고도 상승이 실제 이동 고도보다 크게 부풀지 않는지, 페이스가 비정상적으로 빠르게 표시되지 않는지 QA 보고서에 기록한다.

## 4. 완료 기준

- GPS 고도 노이즈만 있는 합성 샘플에서 고도 상승이 누적되지 않는다.
- 실제로 지속되는 상승 샘플은 누락되지 않고, 단일 급격한 이상치는 제한된다.
- 러닝 중·종료 후 고도 상승이 동일한 계산 기준으로 표시·저장된다.
- 정지·일시정지·GPS 스파이크 상황에서 페이스가 빠르게 튀지 않는다.
- 정상 러닝 구간의 평균 페이스와 1km 랩 페이스가 시간/거리 기준에 맞는다.
- 3개 지표 슬롯을 어느 순서로 탭해도 전체 지표 목록이 중복 없이 순서대로 노출된다.
- 기존 기록의 고도·심박수·케이던스가 없는 경우에도 화면이 정상 표시된다.

## 5. 작업 절차

1. 본 계획서 검토 및 승인
2. 승인 후 GitHub 이슈 작성
3. 이슈 번호를 반영한 `fix/<번호>-running-metrics` 브랜치 생성
4. 계산 정책/테스트 → 고도 보정 → 페이스 보정 → 지표 UI 순서로 작은 태스크 단위 구현
5. 의미 있는 단위로 커밋 및 QA
6. 최종 보고서 작성, 푸시, PR 생성
7. PR 검토 및 머지는 개발자가 직접 진행

## 6. 확인이 필요한 결정

- 지표의 기준 순서는 현재 제안한 `km → 고도 상승 → 페이스 → BPM → 케이던스 → 칼로리`로 진행한다.
- 슬롯을 탭했을 때 기존 슬롯의 값을 다음 미표시 지표로 교체하는 방식으로 진행한다. 즉, 탭한 위치를 고정하지 않고 전체 순서를 소비한다.
- 고도 계산은 수직 정확도가 낮은 샘플과 단일 급변값을 보수적으로 제외하되, 실제 러닝에서 확인 가능한 상승은 보존하는 방향으로 조정한다.
