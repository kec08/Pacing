# fix Realtime Database 러너 활성 상태 복구 계획서

## 목적

현재 접속 중인 사용자의 위치가 Realtime Database `activeRunners/{uid}`에 갱신되지 않고, 오래된 노드가 남아 지도 친구 핀과 주변 러너 목록이 비는 문제를 해결한다. 추가로 러닝 중 내 위치 갱신에 맞춰 지도 카메라가 사용자를 자연스럽게 추적하도록 복구한다.

## 확인된 현상

- 2026-08-11 운영 DB 조회 시 활성 러너 노드의 마지막 갱신 시각이 2026-07-21, 2026-07-27로 확인됐다.
- 지도는 `activeFriendRunners`, 주변 목록은 `nearbyRunners`를 사용하므로 현재 활성 데이터가 없으면 두 영역이 모두 비어 보인다.
- 현 구현은 Realtime Database 쓰기 실패와 오래된 노드를 정상 빈 상태로 처리해 원인을 사용자와 개발자가 확인할 수 없다.

## 사용자 시나리오

1. 사용자 A와 B가 서로 친구이며, 두 기기에서 러닝 탭을 열고 위치 권한을 허용한다.
2. 각 기기는 5초 이내에 `activeRunners/{uid}`에 유효한 좌표와 갱신 시각을 기록한다.
3. A 지도에는 B 핀이 표시되고, 1km 이내라면 A의 주변 러너 목록에도 B가 표시된다.
4. 앱 연결이 끊기거나 일정 시간 갱신되지 않은 러너는 표시 대상에서 제외된다.
5. 사용자 A가 러닝을 시작하면 지도는 현재 위치를 따라 이동한다. 지도를 직접 드래그하거나 확대·축소하면 자동 추적은 일시 중지되고, 내 위치 버튼을 누르면 재개된다.

## 데이터 흐름

`LocationManager.currentLocation` →

- `RealtimeDBService.refreshBroadcast` → `activeRunners/{uid}` → `observeActiveRunners` → `NearbyRunnerViewModel` → 지도 및 주변 러너 시트
- `RunningView` 카메라 추적 상태 → `MapCameraPosition` → 현재 위치 중심 지도

## 작업 항목

1. Realtime Database 활성 러너 규칙을 소스 관리 대상에 추가하고, 인증 사용자에게 필요한 읽기/본인 노드 쓰기 권한을 명시한다.
2. 브로드캐스트 쓰기 완료/실패를 수신해 재시도 가능한 상태와 진단 로그를 제공한다.
3. 좌표가 없거나 일정 시간 갱신되지 않은 노드는 수신 단계에서 제외한다.
4. 친구 목록 조회 실패와 Realtime Database 수신 실패를 빈 상태와 구분해 화면에 전달한다.
5. 러닝 시작·위치 갱신 시 카메라 추적, 사용자 수동 조작 시 중지, 내 위치 버튼으로 재개하는 상태 전환을 정리한다.
6. 단위 테스트와 실기기 2계정 QA로 지도 친구 핀·1km 주변 목록·연결 종료 후 정리·러닝 중 지도 추적을 검증한다.

## 완료 기준

- [ ] 운영 DB에 현재 접속 기기의 `updatedAt`이 5초 내 갱신된다.
- [ ] 상호 친구는 지도에 표시된다.
- [ ] 1km 이내 러너는 주변 러너 목록에 표시된다.
- [ ] 2분 이상 갱신되지 않은 노드는 지도와 목록에서 제외된다.
- [ ] 권한 거부·DB 읽기/쓰기 실패가 빈 상태가 아닌 오류 상태로 표시된다.
- [ ] 러닝 중 위치가 갱신되면 지도 카메라도 현재 위치를 따라간다.
- [ ] 사용자의 수동 지도 조작은 자동 추적을 중지하며, 내 위치 버튼으로 재개된다.
