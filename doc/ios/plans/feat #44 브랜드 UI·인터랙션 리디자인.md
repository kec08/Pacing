## 1. 목적 및 배경

현재 앱 시작 화면은 흰 배경 위 시스템 러닝 아이콘과 텍스트를 사용해, 실제 앱 아이콘의 핑크·퍼플 그라디언트와 브랜드 인상이 연결되지 않는다. 홈·러닝·음악 화면도 기능은 갖추고 있으나 카드, 전환, 로딩, 탭 이동의 시각적 리듬이 약해 음악과 러닝을 함께 쓰는 앱만의 몰입감이 부족하다.

이번 작업은 제공된 앱 아이콘의 색감과 둥근 실루엣을 Pacing의 브랜드 기준으로 삼아, 스플래시·탭·핵심 카드·재생 경험을 일관되게 정리한다. 음악 앱에서 느껴지는 깊이 있는 레이어와 앨범 아트 중심의 몰입감은 참고하되, Spotify의 고유 UI·자산을 복제하지 않고 Pacing만의 핑크·퍼플 러닝 경험으로 구현한다.

## 2. 사용자 시나리오

```
사용자가 앱을 실행한다
→ 아이콘과 연결된 그라디언트 배경 위에서 Pacing 브랜드 마크가 자연스럽게 등장한다
→ 세션 복원이 끝나면 현재 화면으로 부드럽게 전환된다
→ 홈·음악·러닝 탭을 이동할 때 선택 상태와 카드 계층이 명확히 보인다
→ 음악을 재생하거나 러닝을 시작할 때 촉각 피드백과 절제된 모션으로 상태 변화를 즉시 인지한다
→ Reduce Motion 설정 시 필수 상태 전환만 유지하고 장식적 모션은 축소된다
```

## 3. 디자인 방향 및 화면 구성

### 브랜드 방향

- **색상**: 앱 아이콘을 기준으로 한 코랄 핑크 → 마젠타 → 바이올렛 그라디언트. 기능 상태 색상은 충분한 대비를 유지한다.
- **톤**: 선명한 컬러 포인트, 깊이 있는 배경 레이어, 둥근 연속 모서리, 큰 제목과 간결한 메타데이터를 사용한다.
- **음악 경험**: 앨범 아트, 재생 상태, 진행 표시를 전면에 배치하되 러닝 중 시인성과 조작 안전성을 우선한다.
- **독창성**: 일반적인 음악 앱의 정보 계층은 참고하되, 타 서비스의 고유 레이아웃·카피·아이콘 조합을 복제하지 않는다.

### 스플래시 및 진입

- 앱 아이콘과 동일 계열의 풀스크린 그라디언트 배경 적용
- 중앙의 신규 Pacing 브랜드 마크와 `Pacing` 워드마크 적용
- 마크는 작은 스케일·투명도에서 한 번만 자연스럽게 등장하며, 배경 장식·펄스·빛 번짐·반복 효과는 적용하지 않음
- 인증·프로필 복원 완료 후 콘텐츠 화면으로 페이드/스케일 전환
- 시스템 시작 화면(Launch Screen)은 정적 브랜드 배경·마크로 맞추고, 앱 실행 후 SwiftUI 스플래시에서 모션을 담당

### 전역 UI 기반

- `PacingColor`를 브랜드 그라디언트, 표면, 텍스트, 상태 토큰으로 확장
- 재사용 가능한 `PacingGradientBackground`, `PacingSurfaceCard`, `PacingPressStyle`, `PacingEmptyState` 구성
- 탭 바 선택 상태를 명확히 하고 러닝 탭을 중심 행동으로 인지할 수 있게 강조
- 라이트/다크 모드에서 배경·텍스트·카드 대비를 유지하고, 현재 강제 라이트 모드 사용 지점을 점검

### 핵심 화면 우선순위

1. **홈 탭**: 인사말, 주간 러닝, 최근 기록, 같이 들은 러너를 카드 계층과 점진적 등장 모션으로 재구성
2. **러닝 탭**: 지도 위 음악 카드·러닝 통계·컨트롤을 글래스 표면과 브랜드 그라디언트로 정리. 큰 조작 영역과 주행 중 가독성 유지
3. **음악 탭/시트**: 앨범 아트, 현재 곡, 재생 컨트롤, 플레이리스트를 앨범 중심 레이아웃과 미니 플레이어 전환으로 정리
4. **친구·마이 탭**: 기존 데이터 흐름을 유지하며 프로필·빈 상태·리스트 행의 표면과 상호작용을 통일

## 4. 데이터 흐름 및 아키텍처

### 유지 원칙

- ViewModel, UseCase, Repository 및 Firebase/MusicKit 데이터 흐름은 변경하지 않는다.
- UI 상태·애니메이션 상태는 각 View 또는 재사용 UI 컴포넌트에 한정한다.
- 재생·러닝·같이 듣기 비즈니스 로직을 스타일 변경 과정에서 View로 옮기지 않는다.

### 신규 UI 상태

- `SplashView`: 로고 등장 단계, 인증 복원 완료 전환 상태
- `MainTabView`: 선택 탭 전환 시각 상태와 접근성 레이블
- 음악/러닝 화면: 카드 확장, 시트 전환, 버튼 누름 상태만 View 레이어에서 관리
- 접근성: `accessibilityReduceMotion` 및 Dynamic Type을 반영해 모션·레이아웃을 조정

### 이미지 에셋

- 제공 이미지 역할:
  - 앱 아이콘 PNG: 기존 브랜드의 색상·광택·둥근 실루엣 레퍼런스
  - 현재 스플래시 캡처: 개선 전 화면과 비교할 기준
- 신규 생성 자산:
  - 중앙 스플래시용 Pacing 브랜드 마크 1종(텍스트 없는 심볼, 앱 아이콘과 동일한 핑크·퍼플 무드)
  - 필요 시 동일 마크의 밝은 배경/어두운 배경 대응 변형
- 생성 자산은 기존 AppIcon을 임의로 덮어쓰지 않고 별도 에셋으로 추가한 뒤, 시각 검토 후 적용한다.

## 6. 완료 기준 (Acceptance Criteria)

- [ ] 앱 시작 시 기존 흰 배경·시스템 러닝 아이콘 대신 브랜드 그라디언트와 Pacing 마크가 표시된다.
- [ ] Launch Screen과 SwiftUI 스플래시가 시각적으로 연결되며, 인증 복원 중 빈 흰 화면이 노출되지 않는다.
- [ ] 스플래시 모션은 로고의 짧은 1회 등장만 사용해 앱 진입을 방해하지 않으며, Reduce Motion에서는 즉시 표시된다.
- [ ] 홈·러닝·음악·친구·마이 탭의 카드·색상·타이포그래피·빈 상태가 공통 디자인 토큰을 사용한다.
- [ ] 러닝 중 음악 조작, 러닝 시작/일시정지/종료, 같이 듣기 기능이 기존과 동일하게 동작한다.
- [ ] 모든 주요 조작 요소가 최소 44pt 터치 영역과 VoiceOver 레이블을 충족한다.
- [ ] 라이트/다크 모드, Dynamic Type, 작은 iPhone 화면에서 텍스트 겹침·대비 부족이 없다.
- [ ] iOS Simulator 빌드와 UI 테스트가 성공하며, 실기기에서 스플래시·탭·러닝·음악 모션의 프레임 드롭이 없는지 확인한다.

## 7. 특이 사항 / 기술 검토

- Apple의 Launch Screen은 정적 화면만 허용하므로 애니메이션은 앱이 실행된 뒤 `SplashView`에서 구현한다.
- `TimelineView` 또는 반복 타이머를 사용하지 않는다. 스플래시는 로고의 단발성 상태 기반 애니메이션만 사용해 배터리와 러닝 중 성능을 보호한다.
- iOS 접근성의 Reduce Motion 설정을 우선하며, 장식적 자동 반복 애니메이션은 비활성화 또는 정지된 상태로 대체한다.
- 새 이미지 자산은 앱 번들 크기를 고려해 필요한 해상도와 압축 품질을 검토한다. AppIcon 교체는 별도 검토 항목이며 이번 작업에서 자동으로 교체하지 않는다.
- 전면 리디자인이지만 데이터 모델·인증·러닝 측정·음악 재생·같이 듣기 동기화 로직은 변경 범위에서 제외한다.
- 계획 검토·승인 후 GitHub 이슈 생성, `dev` 기준 `feat/44-brand-ui-interaction-refresh` 브랜치 분기, 기능 단위 커밋 순으로 진행한다.
