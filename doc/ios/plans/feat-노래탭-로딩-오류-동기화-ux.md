## 1. 목적 및 배경

노래 탭의 Apple Music 추천 데이터는 여러 MusicKit 요청을 순차적으로 수행한다. 현재 첫 진입에서 일부 요청이 아직 진행 중이어도 빈 데이터 상태가 먼저 렌더링되어, 사용자는 실제 오류처럼 보이는 안내 카드를 잠시 보게 된다. 또한 추천 요청의 일시적 실패가 즉시 전역 오류 얼럿으로 노출되어, 잠시 뒤 콘텐츠가 로드되는 상황에서도 불필요한 오류 피드백이 발생한다.

이를 해결해 첫 로딩과 새로고침 중에는 각 섹션에서 스켈레톤 UI를 유지하고, 실제로 재시도해도 로드할 수 없는 실패만 오류로 안내한다. 수동 동기화 버튼은 제거하고, 아래로 당겨 새로고침할 때 라이브러리 플레이리스트 동기화가 함께 수행되도록 단일 진입점으로 정리한다.

## 2. 사용자 시나리오

```
사용자가 노래 탭에 처음 진입하거나 아래로 당겨 새로고침하면
→ 친구/Apple Music 콘텐츠가 로드되는 동안 각 섹션의 스켈레톤을 확인하고
→ 성공 시 콘텐츠 또는 정상 빈 상태를 확인한다.

일시적인 MusicKit 요청 실패가 발생하면
→ 즉시 오류 얼럿을 띄우지 않고 로딩 상태를 유지한 뒤 재시도한다.

재시도 후에도 필수 추천 콘텐츠를 불러오지 못한 경우에만
→ 노래 탭 오류 얼럿으로 실패를 안내한다.
```

## 3. 화면 구성

### 주요 화면

- 노래 탭: 상단 `내 플레이리스트 동기화` 버튼을 제거한다.
- 친구·최근 앨범·장르·무드·추천 섹션: 데이터가 없고 로딩 중이면 기존 스켈레톤 행을 표시한다.
- 노래 탭 오류 얼럿: 복구 불가능한 최종 실패에만 표시한다.

### UI 요소

- Pull-to-refresh: Apple Music 라이브러리 동기화와 추천 콘텐츠 갱신을 함께 실행한다.
- SkeletonView: 콘텐츠 도착 전 오류/빈 상태 안내 카드를 대체한다.
- 빈 상태 카드: 로딩 완료 후 데이터가 실제로 없는 경우에만 표시한다.

## 4. 데이터 흐름

### 사용 데이터

- Firestore: 친구 공개 플레이리스트 조회 및 내 플레이리스트 저장
- MusicKit: 라이브러리 플레이리스트, 최근 재생 앨범, 개인화/차트 추천, 장르·무드 검색

### 상태 관리

- `SongViewModel`
  - 섹션별 로딩 상태를 Apple Music 전체 추천 로딩 수명과 일치시킨다.
  - 새로고침 요청에는 내 라이브러리 동기화를 포함한다.
  - 일시 오류는 제한된 재시도 후 최종 실패일 때만 `errorMessage`에 반영한다.
- `SongView`
  - 상단 수동 동기화 버튼과 그 전용 로딩 상태 표현을 제거한다.
  - 로딩 여부를 기준으로 스켈레톤/빈 상태/콘텐츠를 전환한다.

## 6. 완료 기준 (Acceptance Criteria)

- [ ] 노래 탭 최초 진입 중 모든 비어 있는 추천 섹션이 오류 카드 대신 스켈레톤을 표시한다.
- [ ] 아래로 당겨 새로고침하는 동안 기존 데이터가 없던 섹션은 스켈레톤을 표시한다.
- [ ] 일시적인 추천 요청 실패로 즉시 `노래 탭 오류` 얼럿이 표시되지 않는다.
- [ ] 재시도 후 최종 실패일 때만 오류 얼럿이 표시된다.
- [ ] 상단 `내 플레이리스트 동기화` 버튼이 사라지고, Pull-to-refresh는 내 플레이리스트 동기화를 계속 수행한다.
- [ ] 기존 정상 빈 상태(최근 재생 없음, 친구 플레이리스트 없음)는 로딩 완료 후 그대로 유지된다.

## 8. 검토 결과 / 기술 검토

- 검토 완료: 기존 `SongViewModel`은 장르·무드 전용 로딩 상태가 없어 추천 호출 도중 빈 배열이 오류 카드로 렌더링될 수 있다. 전체 추천 로딩 상태를 두 섹션에도 적용한다.
- MusicKit의 네트워크/카탈로그 응답은 일시 실패 가능성이 있어, 최초 실패를 사용자 오류로 확정하지 않는다. 재시도는 제한 횟수와 짧은 지연을 사용해 UI 응답성을 유지한다.
- 권한 거부·구독 미지원은 네트워크 재시도로 해결되지 않는 상태이므로 기존 권한 안내 카드로 유지하고 전역 오류 얼럿 대상에서 제외한다.
- 기존 사용자 수정 파일(`project.pbxproj`, `Pacing.entitlements`)은 이번 작업 범위에서 변경하거나 커밋하지 않는다.
