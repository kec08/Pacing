## 1. 목적 및 배경

홈의 `이번 주 러닝`과 마이페이지의 주간 통계가 서로 다른 주 시작일을 사용해 동일한 기록이 다르게 집계된다. 또한 홈 화면의 친구 콘텐츠 밀도를 높이고, 친구 음악·러닝 관련 UI를 개선한다.

## 2. 사용자 시나리오

```
사용자가 홈과 마이페이지에서 이번 주 러닝을 확인하면
→ 두 화면이 월요일~일요일 기준으로 같은 기록을 집계하고
→ 홈에서 친구의 최신 러닝과 최근 음악을 자연스럽게 탐색하며
→ 친구 프로필에서도 최근 러닝 기록을 확인한다.
```

## 3. 화면 구성

### 홈

- 이번 주 러닝: 월요일 시작 공통 주간 범위로 거리·시간·평균 페이스 표시
- 친구 최근 러닝: 내 최근 러닝과 같은 카드 밀도(루트 썸네일, 날짜, 거리, 시간, 평균 페이스)로 최신 활동 노출
- 친구가 최근에 들은 음악: 앨범 커버를 확대하고, 카드 간 간격을 축소하며, 닉네임 뒤 `님` 제거

### 러닝 활동 상세

- km별 평균 페이스: 두 자리 km도 줄바꿈되지 않는 고정 폭 레이블 적용

### 친구 프로필

- 누적 통계 아래에 최근 러닝 목록 추가
- 로딩·빈 상태·오류 상태를 최근 음악 섹션과 동일한 UX 수준으로 제공

## 4. 데이터 흐름

### 사용 데이터

- Firestore `users/{uid}/runHistory`: 내 러닝, 친구 최신 러닝, 친구 프로필 최근 러닝
- Firestore `users/{uid}/friends`: 친구 목록과 표시 닉네임
- Firestore `users/{uid}/recentSongs`: 홈 친구 최근 음악

### 상태 관리

- `WeeklyDateRange` 또는 동등한 공통 계산 로직: 월요일 00:00부터 다음 월요일 00:00까지의 범위를 제공
- `HomeViewModel`: 주간 통계, 최근 내 러닝, 친구 최신 러닝, 친구 최근 음악을 병렬 로드
- `MyViewModel`: 공통 주간 범위를 사용해 통계와 차트를 계산
- `FriendProfileViewModel`: 친구 프로필·누적 통계·최근 음악·최근 러닝을 병렬 로드

- [x] 동일한 러닝 기록이 홈과 마이페이지에서 같은 주에 동일하게 집계된다.
- [x] 일요일 기록은 다음 날 월요일부터 새 주 기록으로 중복 없이 구분된다.
- [x] 10km 이상 구간 라벨이 줄바꿈되지 않는다.

- [x] 홈과 친구 프로필에서 친구의 최근 러닝을 로딩·빈·오류 상태와 함께 확인할 수 있다.

## 8. 특이 사항 / 기술 검토

- 현재 홈은 기기 캘린더의 주 시작일 설정을 따르고, 마이페이지는 월요일 시작을 명시한다. 두 화면을 공통 로직으로 통일한다.
- 친구 러닝은 현재 친구 관계가 성립된 사용자 데이터만 조회한다. 별도의 공개 범위 모델은 추가하지 않는다.
- 내 러닝 상세 화면을 재사용하되, 친구 기록임을 카드의 닉네임으로 명확히 표시한다.
- 기존 미커밋 변경인 앱 버전 및 entitlement 설정은 본 기능 범위에서 제외하고 보존한다.
