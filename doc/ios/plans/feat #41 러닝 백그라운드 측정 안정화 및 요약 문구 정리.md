## 1. 목적 및 배경

현재 러닝 기능은 시간은 백그라운드에서도 계속 누적되지만, 거리, 경로, 평균 페이스, 칼로리 계산은 앱이 백그라운드로 전환되면 정상적으로 이어지지 않고 있다.
이 상태에서는 실제 러닝 앱의 핵심 사용성인 "앱을 보지 않아도 기록이 계속 남는 경험"이 깨진다.

또한 러닝 종료 요약 화면의 문구가 사용자 기대와 완전히 맞지 않는다.
상단 핵심 지표는 `평균 페이스`로 보여주고, 하단 km 단위 상세 리스트는 `km 평균 페이스` 의미가 더 명확하게 전달되도록 정리할 필요가 있다.

이번 작업은 앱 아이콘은 그대로 유지하면서, 러닝 측정의 백그라운드 지속성을 우선 해결하고, 종료 요약 화면의 페이스 문구를 더 명확하게 다듬는 것을 목표로 한다.

## 2. 사용자 시나리오

```text
사용자가 러닝을 시작하면
→ 앱을 백그라운드로 보내거나 화면을 꺼도 시간, 거리, 경로, 평균 페이스, 칼로리 계산이 계속 이어지고
→ 다시 앱에 복귀했을 때 누락 없이 현재 러닝 상태와 경로가 이어지며
→ 러닝 종료 후 요약 화면에서 상단은 `평균 페이스`, 하단은 `km 평균 페이스` 성격의 리스트로 자연스럽게 결과를 확인한다
```

## 3. 화면 구성

### 주요 화면
- 러닝 화면: 백그라운드 전환 후에도 측정 상태가 유지되어야 함
- 러닝 종료 요약 화면: 페이스 문구와 km 단위 상세 정보 정리

### UI 요소
- 앱 아이콘: 변경 없음
- 종료 요약 상단 카드: `시간 / 평균 페이스 / 칼로리`
- 종료 요약 하단 섹션 제목: `km 평균 페이스`
- km 단위 상세 행: `1km`, `2km`, `3km` 등 랩 기준 평균 페이스 표시

## 4. 데이터 흐름

### 사용 데이터
- `CLLocationManager` 위치 업데이트 및 배치 위치 배열
- `RunningViewModel` 누적 시간, 거리, 평균 페이스, 칼로리 계산 값
- `RunSummaryView` 종료 요약 렌더링 데이터
- Firestore `runHistory` 저장 데이터

### 상태 관리
- `LocationManager`
  - 백그라운드 위치 업데이트 허용 여부
  - 경로 좌표 누적
  - 배치 위치 수신 처리
- `RunningViewModel`
  - 시간 누적 동기화
  - 거리 누적
  - 평균 페이스 계산
  - km 랩 평균 페이스 목록 유지
- `RunSummaryView`
  - 상단 평균 페이스 표시
  - 하단 km 평균 페이스 리스트 표시

## 8. 특이 사항 / 기술 검토

- 현재 코드상 `LocationManager`는 `allowsBackgroundLocationUpdates`를 켜는 분기가 있으나, `Info.plist`에 `UIBackgroundModes`가 확인되지 않아 실제 백그라운드 위치 추적 조건이 충족되지 않은 상태다.
- `requestAlwaysAuthorization()` 호출만으로 충분하지 않고, 사용자 권한 상태와 앱 설정이 함께 맞아야 한다.
- 시간은 `Date` 기반 누적으로 유지되지만, 거리와 경로는 `didUpdateLocations` 수신이 끊기면 함께 멈추므로 위치 수신 지속성이 핵심이다.
- 칼로리는 거리 기반 파생값이므로, 거리 측정이 정상화되면 함께 안정화된다.
- km 상세 리스트는 현재 구현상 완료된 1km 랩 기준 데이터가 있으므로, 이번 작업에서는 문구를 더 명확히 정리하는 방향이 우선이다.
- 앱 아이콘은 이번 개발 범위에서 수정하지 않는다.
- 백그라운드 동작 검증은 시뮬레이터보다 실기기 검증이 우선이다.
