# 러닝 고도 상승값 보정 계획서

## 1. 목적

동일 러닝에서 Nike Run은 고도 상승 16m, Pacing은 109m를 표시한 사례를 기준으로, GPS 수직 오차가 반복 누적되어 고도 상승이 과대 표시되는 문제를 보정한다. 러닝 중 표시값, 종료 요약, 저장 기록이 반드시 같은 계산 결과를 사용하도록 유지한다.

## 2. 확인 결과

- 현재 `RunMetricsCalculator.elevationGain`은 수직 정확도 10m 이하 샘플, 5개 중앙값, 5m 이상 연속 상승, km당 30m 상한을 사용한다.
- 수직 정확도 10m는 인접 두 고도값의 오차 범위에 비해 충분히 작지 않다. 따라서 5m 상승을 2회 확인하는 규칙은 평지의 반복적인 GPS 상향 흔들림도 실제 상승으로 누적할 수 있다.
- 고도 샘플은 거리 계산을 통과한 구간에만 수집된다. 거리 유효성은 수직 고도의 신뢰성을 보장하지 않으므로, 고도 전용 정책이 더 보수적이어야 한다.
- `pause → resume` 시 고도 샘플 배열이 초기화되어, 누적 상승의 전체 세션 정합성도 별도로 보완해야 한다.

## 3. 구현 계획

### Task 1. 고도 계산 정책 분리 및 회귀 테스트

- 수직 정확도·시간 순서·수평 이동 거리의 유효성 기준을 `RunMetricsCalculator`의 명시적 정책으로 정의한다.
- 평지 반복 노이즈, 단일 스파이크, 낮은 정확도, 지속 상승, pause/resume 연결, 실제 완만한 상승의 합성 위치 테스트를 추가한다.
- 비교 스크린샷 사례(8km, Nike Run 16m / Pacing 109m)를 수용 기준의 실기기 검증 샘플로 기록한다.

### Task 2. 노이즈 누적 방지 알고리즘 적용

- 더 작은 수직 오차 샘플만 허용하고, 주변 샘플의 중앙값/시간·거리 창으로 고도를 안정화한다.
- 개별 양의 변화량을 즉시 합산하지 않는다. 최저점 대비 충분한 높이와 거리 동안 유지된 상승 구간만 확정하는 히스테리시스 방식으로 변경한다.
- 실제 상승을 과도하게 제거하지 않도록 상승 확정 임계값과 거리 비례 상한을 테스트 경계로 관리한다.

### Task 3. 세션 수집 경로 정합성

- 고도 계산용 위치 배열을 pause/resume 전체 러닝 세션 기준으로 유지한다.
- 거리 측정 정책과 분리하되, 타임스탬프 역행·유효하지 않은 수직 정확도·비정상 수평 이동은 고도 입력에서 제외한다.
- 실시간 계산, 종료 시 계산, Firestore 저장에 같은 입력과 계산 함수를 사용한다.

### Task 4. QA

- `PacingTests`의 고도 계산 회귀 테스트와 Debug iOS Simulator 빌드를 실행한다.
- 실기기에서 평지/완만한 오르막 러닝을 기록해 Nike Run 또는 고도 지도와 비교한다. 외부 서비스의 값은 구현의 절대 정답이 아니라 과대 누적 방지의 비교 기준으로 사용한다.
- 기존 기록, 위치 권한 거부, 고도 유효 샘플 부족 시 `--` 또는 기존 안전 표시가 유지되는지 확인한다.

## 4. 완료 기준

- 평지성 반복 고도 노이즈가 누적 상승으로 이어지지 않는다.
- 지속적이고 완만한 실제 상승은 계산 결과에 남는다.
- pause/resume 이후에도 앞선 세그먼트의 상승값이 사라지지 않는다.
- 러닝 중, 종료 요약, 상세 화면, 저장 레코드의 고도 상승 값이 일치한다.
- 단위 테스트와 Debug iOS Simulator 빌드가 통과한다.
- 실기기 비교 결과와 남은 오차 한계를 QA 보고서에 기록한다.
