# 러닝 고도 상승 기압계 보정 계획서

## 1. 목적

동일 7.50km 러닝에서 Nike Run은 고도 상승 12m, Pacing은 152m를 기록한 과대 집계 문제를 해결한다. GPS 절대 고도만으로 누적 상승을 계산하는 방식에서 벗어나, 지원 기기의 기압계 상대 고도를 우선 사용해 실제 짧은 거리 러닝의 상승값을 안정적으로 계산한다.

## 2. 재현 결과

| 서비스 | 거리 | 시간 | 고도 상승 |
| --- | ---: | ---: | ---: |
| Nike Run | 7.50km | 40:08 | 12m |
| Pacing | 9.02km | 47:21 | 152m |

두 앱의 거리·시간도 달라 같은 러닝의 GPS 샘플링·필터 기준이 서로 다르다. 그러나 Pacing의 152m는 Nike Run 12m 대비 약 12.7배로, 일반적인 GPS 차이 범위를 넘어선다.

## 3. 확인된 원인

### 3.1 반복 GPS 드리프트를 상승으로 합산하는 식

현재 `RunMetricsCalculator.elevationGain`은 중앙값 처리 후 다음 규칙을 사용한다.

1. 고도가 저점보다 12m 이상 높아지면 후보 정점으로 유지한다.
2. 이후 8m 이상 내려가면 `정점 - 저점` 전체를 상승값으로 합산한다.
3. 다음 저점부터 동일 과정을 반복한다.

`CLLocation.altitude`의 수직 오차는 수평 이동이 정상이어도 시간에 따라 완만하게 드리프트할 수 있다. 따라서 12m 이상 오르고 8m 이상 내려오는 GPS 파형이 여러 번 발생하면 각각이 실제 오르막으로 확정된다. 7.5km에서는 현재 거리 상한이 `7.5 × 30m = 225m`이므로, 152m는 상한보다 작아 그대로 저장된다.

### 3.2 입력 신뢰성 한계

- `verticalAccuracy <= 5m`는 개별 측정의 허용 오차이며, 여러 샘플 간 상대 변화가 실제 고도 변화라는 보장은 아니다.
- 고도 샘플은 러닝 거리 구간의 GPS 유효성 검사를 통과하면 수집된다. 수평 거리 유효성은 수직 고도 신뢰성과 독립적이다.
- 원시 고도·수직 정확도·계산된 상승 구간을 저장하지 않아, 종료 후 152m를 만든 개별 봉우리를 재현·감사할 수 없다.

## 4. 구현 계획

### Task 1. 고도 입력 소스 분리

- `ElevationRepository` 추상화를 도입한다.
- `CMAltimeter`가 지원되는 실기기에서는 기압계의 `relativeAltitude`를 러닝 시작 기준으로 수집한다.
- 기압계 값을 사용할 수 없는 기기는 GPS 고도 보수적 fallback으로 처리하며, 입력 소스를 명시한다.

### Task 2. 기압계 기반 누적 상승 계산

- 기압계 상대 고도의 중앙값/히스테리시스 필터를 적용한다.
- GPS 방식의 반복 저점·정점 전량 합산을 제거하고, 작은 압력 노이즈는 누적하지 않는다.
- 러닝 중 표시, 종료 요약, Firestore 저장이 같은 고도 입력과 계산 정책을 공유한다.
- pause/resume 시 기압계 기준점과 누적 상승을 보존하고, 재개 직후 기준점 점프를 제외한다.

### Task 3. GPS fallback 및 관측 가능성

- GPS fallback의 최대 상승 상한을 현재 30m/km보다 보수적으로 재검토한다.
- 디버그 로그 또는 테스트 가능한 진단 모델로 입력 소스, 유효 샘플 수, 확정 상승 구간을 기록한다.
- 고도 입력이 부족하면 0을 임의 저장하지 않고 기존 `--` 표시 정책을 유지한다.

### Task 4. 회귀 테스트와 QA

- 반복 GPS 드리프트가 현재 식에서 152m 수준으로 누적되는 합성 샘플을 추가하고, 새 정책에서 제한되는지 검증한다.
- 지속적인 실제 상승·평지·pause/resume·기압계 미지원 fallback 테스트를 추가한다.
- 실기기에서 동일/유사 평지 7.5km 경로를 Nike Run과 비교하고, 고도 상승·거리·시간을 함께 기록한다.

## 5. 완료 기준

- 반복 GPS 고도 드리프트가 누적 상승으로 과대 합산되지 않는다.
- 지원 기기에서 기압계 상대 고도를 사용한다.
- 7.5km 평지성 러닝에서 Pacing의 상승값이 기존 152m처럼 비정상적으로 높지 않다.
- 실제 지속 상승은 누락되지 않는다.
- 러닝 중·종료 요약·상세·저장 기록의 값이 일치한다.
- 입력 소스와 실기기 비교 결과를 QA 보고서에 남긴다.
