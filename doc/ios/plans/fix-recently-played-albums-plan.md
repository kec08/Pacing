# 최근에 들은 앨범 표시 복구 계획

## 상태

과거 조회 흐름 복구 완료 · 실기기 QA 대기

## 관련 이슈

- [#206 최근에 들은 앨범 목록 표시 복구](https://github.com/kec08/Pacing/issues/206)

## 배경

음악 탭의 최근에 들은 앨범은 최근 재생 컨테이너의 제한된 첫 응답에서 앨범만
필터링한다. 플레이리스트 또는 스테이션 항목이 앞에 몰리면, 더 이전에 재생한 앨범이
있어도 빈 상태가 노출된다.

## 목표

- 최근 재생 기록을 페이지 단위로 조회해 앨범 최대 8개를 안정적으로 구성한다.
- 중복 앨범을 제거하고, 빈 기록과 요청 실패의 기존 UX를 유지한다.
- 기존 친구 기능 변경과 독립적으로 검증한다.

## 작업 범위

1. 과거 정상 동작 시점과 같이 `MusicRecentlyPlayedRequest<RecentlyPlayedMusicItem>`으로 최근 컨테이너 이력을 직접 요청한다.
2. 컨테이너에 앨범이 없거나 부족한 경우 `MusicRecentlyPlayedRequest<Song>`으로 곡 이력을 조회하고 소속 앨범을 보완한다. 두 요청은 독립 처리해 한쪽 실패가 다른 쪽의 정상 결과를 제거하지 않게 한다.
3. 장르·무드·추천 플레이리스트 요청과 최근 앨범 요청을 분리한다.
4. 추천 카탈로그 요청이 실패해도 이미 조회한 최근 앨범 목록을 빈 상태로 덮어쓰지 않는다.
5. `ApplicationMusicPlayer`에서 실제 재생한 곡의 앨범을 기기 로컬 이력에 즉시 저장하고 Apple Music 이력과 합쳐 표시한다.
6. 음악 탭 재진입 시 최근 앨범을 별도로 다시 조회한다.
7. 정적 검증과 iOS 빌드를 수행하고, 실기기에서 앨범·플레이리스트 재생 이력 모두를 확인한다.

## 제외 범위

- Apple Music 권한 및 구독 흐름 변경
- 추천 플레이리스트·장르 앨범 조회 로직 변경
