## 1. 목적 및 배경

음악 탭의 상세 재생 화면과 친구 플레이리스트 영역은 기본 구조는 갖춰져 있지만, 현재 실제 사용 흐름에서 다음 문제가 남아 있습니다.

- 친구 플레이리스트 카드/상세에서 커버 이미지가 비어 보이는 경우가 있음
- 친구 플레이리스트의 곡 탭 시 재생이 시작되지 않는 경우가 있음
- 하단 미니 플레이어가 어떤 조건에서 계속 고정 노출되는지 재확인 필요
- 상세 재생 화면의 로딩/빈 상태 전환이 다소 거칠고 초기 응답성이 아쉬움
- 상세 재생 화면 하단 플레이리스트 버튼이 실제 곡 리스트 전환 UX와 연결되지 않음

이번 작업의 목표는 기존 음악 탭 구조를 유지하면서, 재생 안정성과 상세 화면 UX를 함께 개선하는 것입니다.

## 2. 사용자 시나리오

```text
사용자가 노래 탭에서 친구 플레이리스트를 선택하면
→ 커버 이미지와 곡 목록이 정상적으로 보이고
→ 특정 곡을 탭하면 해당 곡으로 즉시 전환되며
→ 필요 시 좌상단 플레이리스트 버튼으로 내 플레이리스트 선택 시트를 열고 닫을 수 있다

사용자가 상세 재생 화면에서 하단 플레이리스트 버튼을 누르면
→ 현재 재생 가능한 곡 리스트가 아래에 펼쳐지고
→ 리스트에서 다른 곡을 누르면 재생 곡이 해당 곡으로 전환된다
```

## 3. 화면 구성

### 주요 화면
- `SongView`: 친구 플레이리스트 진입점, 내 플레이리스트 동기화, 미니 플레이어 노출 관리
- `SharedPlaylistDetailView`: 앨범아트/재생 컨트롤/곡 리스트/플레이리스트 토글을 담당하는 상세 재생 화면

### UI 요소
- 좌상단 플레이리스트 버튼: 현재 상단 글래스형 시트 진입 버튼을 좌상단으로 이동
- 하단 플레이리스트 버튼: `list` 텍스트 + 햄버거바 아이콘 조합으로 변경
- 하단 곡 리스트 패널: 3번 이미지처럼 펼쳐지는 해당 플레이리스트의 곡 목록
- 곡 행(Row): 커버, 곡명, 아티스트, 현재 재생 상태 표시, 탭 시 곡 전환
- 로딩 상태: 전체 블로킹보다 섹션별 스켈레톤/지연 없는 전환 우선

## 4. 데이터 흐름

### 사용 데이터
- Firestore 컬렉션: `sharedPlaylists`, `users/{uid}/savedSharedPlaylists`
- MusicKit API:
  - 라이브러리 플레이리스트 동기화
  - 추천/최근 들은 앨범 조회
  - 플레이리스트/앨범 트랙 조회
  - 단일 곡 또는 트랙 목록 재생

### 상태 관리
- `SongViewModel`
  - 친구 플레이리스트 조회
  - 내 플레이리스트 동기화
  - 추천/최근 앨범 로딩 상태 관리
- `SharedPlaylistDetailViewModel`
  - 상세 소스별 트랙 로딩
  - 현재 재생 트랙 추적
  - 전체 재생 / 단일 곡 재생 / 저장 처리
- `SongNowPlayingController`
  - 시스템 플레이어 기반 미니 플레이어 상태 동기화
  - 상세 화면 복귀/축소 상태 관리

## 5. 작업 목록 (Tasks)

  - 라이브러리 기반 플레이리스트에서 catalog ID 부재 시 재생 가능한 fallback 전략 정의
  - 친구 플레이리스트 대표 커버 이미지 fallback 규칙 정의

- [ ] Task 2. 상세 재생 화면 플레이리스트 UX 개편
  - 좌상단에 플레이리스트 선택 버튼 추가
  - 기존 상단 글래스형 내 플레이리스트 선택 시트를 좌상단 버튼 트리거 방식으로 연결

  - 버튼 탭 시 현재 보고 있는 해당 플레이리스트의 곡 목록이 아래에서 리스트 형식으로 펼쳐지고, 곡 선택 시 해당 곡으로 전환되도록 구현

- [ ] Task 3. 미니 플레이어 노출 조건 및 상세 진입 흐름 점검

  - 실제 재생 중/현재 곡 존재/상세 화면 표시 상태에 맞는 노출 기준 정리
  - 필요 시 상세 화면과 미니 플레이어 간 상태 충돌 보정

- [ ] Task 4. 로딩/빈 상태/전환 최적화
  - 초기 진입 시 섹션별 스켈레톤 조건 재정리
  - 상세 트랙 로딩 시 과도한 전체 차단 없이 부분 로딩 적용
  - 로딩 완료 후 리스트/컨트롤 전환 애니메이션 및 상태 피드백 정리

- [ ] Task 5. QA 및 회귀 검증

  - 친구 플레이리스트 곡 탭 재생
  - 추천 플레이리스트/최근 앨범 상세 진입
  - 하단 플레이리스트 펼침/곡 전환
  - 미니 플레이어 노출/복귀/축소 동작 확인

## 6. 완료 기준 (Acceptance Criteria)

- [ ] 친구 플레이리스트 카드 및 상세 화면에서 커버 이미지가 비어 있을 때 fallback 이미지가 자연스럽게 표시된다
- [ ] 친구 플레이리스트 상세에서 곡을 누르면 오류 없이 해당 곡 재생이 시작된다
- [ ] 상세 화면 하단 플레이리스트 버튼을 누르면 현재 보고 있는 해당 플레이리스트의 곡 목록이 리스트 형식으로 펼쳐지고, 리스트에서 다른 곡을 선택하면 해당 곡으로 전환된다
- [ ] 좌상단 버튼으로 내 플레이리스트 선택 UI를 열고 닫을 수 있다
- [ ] 미니 플레이어가 불필요하게 계속 고정 노출되지 않고, 실제 재생 상태 기준으로 일관되게 동작한다
- [ ] 초기 로딩 및 상세 로딩에서 빈 화면/깜빡임 없이 스켈레톤 또는 안내 상태가 표시된다

## 8. 특이 사항 / 기술 검토

- 현재 친구 플레이리스트는 MusicKit 라이브러리 플레이리스트를 Firestore에 동기화한 뒤, 상세 화면에서 `songStoreID`를 사용해 `MusicCatalogResourceRequest`로 다시 재생하고 있습니다.
- 이 구조에서는 라이브러리 기준 `song.id`가 catalog 재생 ID와 다를 가능성이 있어, 친구 플레이리스트 곡 탭 시 재생 실패가 발생할 수 있습니다.
- 대표 커버 이미지도 플레이리스트 자체 artwork가 비어 있는 경우가 있어, 첫 번째 트랙 artwork 또는 placeholder를 fallback으로 사용하는 보정이 필요합니다.
- 하단 플레이리스트 영역은 현재 버튼만 존재하고 실제 리스트 토글 UX가 완성되지 않은 상태라, 선택한 플레이리스트의 트랙 목록을 그대로 하단 리스트로 재사용하는 방향으로 View 상태와 ViewModel 재생 상태를 함께 정리해야 합니다.
- 배경 비주얼은 이번 범위에서 유지하고, 정보 구조와 인터랙션만 3번/4번 이미지 방향으로 개선합니다.
