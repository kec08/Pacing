# #140~#142 프로필·활동 UI 최종 개발 보고서

## 개요

친구 목록에서 프로필 이미지가 누락되는 문제를 보완하고, 내 프로필의 최근 음악 UI를 친구 프로필과 통일했습니다. 홈에서 친구의 최근 러닝 활동 상세로 이동할 때 친구 프로필 헤더도 함께 표시하도록 개선했습니다.

## 변경 사항

- #140 친구 문서에 이미지가 없는 경우에만 원본 사용자 프로필에서 `profileImageBase64`를 보강
- 기존 이미지가 있는 친구는 추가 조회하지 않고, 누락된 프로필만 4개 단위로 제한해 조회
- 이미지 데이터가 없거나 디코딩에 실패하면 기존 이니셜 fallback 유지
- #141 내 최근 들은 노래를 친구 프로필과 같은 앨범 커버·곡명·아티스트·재생 시간 행으로 통일
- 최근 노래 행 전체를 탭할 수 있게 하고 Apple Music 재생 및 실패 상태를 ViewModel에서 관리
- 내 프로필 최근 노래 행에도 친구 프로필과 같은 연한 하단 구분선을 적용
- #142 친구 최근 러닝 상세 상단에 38pt 원형 프로필 이미지, 친구 이름, 최근 활동 상태를 표시
- 홈 친구 최근 러닝 카드에서 프로필 이미지·이름 영역을 친구 프로필 화면으로 연결
- 활동 상세 상단의 친구 프로필 영역도 친구 프로필 화면으로 연결
- 홈 및 활동 상세의 프로필 아바타 크기를 콘텐츠 비율에 맞게 축소
- 홈 화면은 최초 진입 시에만 자동 데이터를 로드해 활동 상세에서 복귀할 때 불필요한 재구성을 방지
- 친구 최근 러닝 카드의 경로 이미지·기록·화살표 영역을 활동 상세 이동 영역으로 확장
- 활동 상세 이동 화살표를 카드 높이 기준으로 세로 중앙 정렬
- 친구 프로필 헤더와 활동 날짜 사이 여백을 소폭 확대
- 기존 `RunActivityDetailView(record:)` 호출은 optional owner context로 유지해 내 활동 상세 동작을 변경하지 않음

## 기술적 고려 사항

- View는 표시와 사용자 입력 전달만 담당하고, 음악 재생은 `MyProfileDetailViewModel`이 수행
- 친구 활동 모델에 프로필 context를 포함해 홈 행과 상세 화면 사이의 데이터 매핑을 명확히 함
- 친구 목록과 홈 활동 모두 기존 제한(friend limit 8) 범위를 유지
- 프로필 이미지가 이미 denormalize된 친구는 추가 Firebase 문서 읽기를 발생시키지 않음
- 이미지 누락 시에만 친구 목록은 최대 4개 단위, 홈 최근 러닝은 활동 대상별 1회 보강 조회
- 다크모드에서도 기존 색상 토큰과 surface border를 사용하며, 작은 화면에서는 텍스트 line limit을 유지
