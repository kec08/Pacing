# fix #57 백그라운드 러닝 지표 중단 QA 보고서

> **작성일**: 2026-07-20
> **관련 이슈**: [#57](https://github.com/kec08/Pacing/issues/57)
> **브랜치**: `codex/fix-57-background-run-metrics`
> **상태**: 실기기 QA 대기

## 수정 내용

- 자동 생성 plist가 `UIBackgroundModes` 배열을 실제 앱 번들에 넣지 못하던 문제를 수정했다.
  - `GENERATE_INFOPLIST_FILE`을 비활성화했다.
  - 정적 `Info.plist`에 `UIBackgroundModes = [location, audio]`와 기존 자동 생성 메타데이터를 명시했다.
- `LocationManager`가 문자열 배열과 단일 문자열 양쪽 형태의 설정값을 안전하게 해석하도록 보강했다.
- 러닝 시작 전 `Always` 위치 권한을 검사한다.
  - 권한이 없으면 측정을 시작하지 않는다.
  - `설정으로 이동`을 포함한 안내 얼럿을 표시한다.
- 위치 모드 해석 및 백그라운드 활성 조건 단위 테스트를 추가했다.

## 실기기 QA 필요 항목

Simulator는 실제 백그라운드 GPS 전달과 화면 잠금을 검증할 수 없으므로, 아래는 실기기에서 확인해야 한다.

1. Pacing 위치 권한을 **항상 허용**으로 설정한다.
2. 러닝 시작 후 홈 화면 이동 또는 화면 잠금 상태에서 2~3분 이동한다.
3. 앱 복귀 후 거리, 페이스, 칼로리와 지도 경로가 백그라운드 이동 구간까지 이어지는지 확인한다.
4. 위치 권한을 `앱 사용 중`으로 바꾼 뒤 시작 버튼을 눌러, 안내 얼럿 및 설정 이동이 표시되는지 확인한다.
5. 일시정지 뒤 화면 잠금 시에는 지표가 증가하지 않고, 재개 후에는 다시 증가하는지 확인한다.

## 알려진 제한

- 앱을 강제 종료하면 iOS 정책상 백그라운드 위치 기록을 보장할 수 없다.
- GPS 환경에 따라 위치 업데이트가 배치로 도착할 수 있어 UI 갱신은 즉시가 아닐 수 있으나, 도착한 배치의 좌표는 누적 처리한다.
