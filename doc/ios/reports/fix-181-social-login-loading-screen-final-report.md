## 문제 분석

Apple 로그인 외의 인증 흐름은 로그인 버튼 영역에만 작은 인디케이터를 표시해 대기 경험이 일관되지 않았다. 외부 로그인 앱에서 복귀하거나 인증 성공 후 프로필을 복원하는 과정에서는 로딩 상태가 해제된 뒤 화면 전환이 이어져 로그인 버튼 화면이 다시 보일 수 있었다.

회원가입 프로필 설정은 단계별 뒤로가기 수단이 부족했고, 뒤로가기 시 단계 화면 또는 로그인 화면이 즉시 교체되어 전환이 끊겨 보였다.

## 구현 내용

### 공통 인증 로딩 화면

- 앱 아이콘, 서비스명, 슬로건, 인디케이터로 구성된 `AuthenticationLoadingView`를 추가했다.
- Apple·Google·Kakao·Naver·이메일 로그인과 이메일 회원가입에 공통 로딩 화면을 적용했다.
- 기존 로그인·회원가입 버튼 내부 인디케이터를 제거했다.
- 인디케이터는 시스템 large 크기에 110% 스케일을 적용해 가시성과 화면 균형을 조정했다.

### 인증 상태 전환 안정화

- 외부 로그인 앱 복귀 뒤 1.5초 후 로딩을 임의로 해제하던 타이머를 제거했다.
- 인증 성공 시 `isAuthLoading`을 `isLoggedIn`보다 먼저 반영하도록 순서를 통일했다.
- 앱 루트 `SplashView`도 공통 로딩 화면을 표시하도록 변경했다.
- `LoginView`가 로그인 성공 후 온보딩을 중복 push하던 흐름을 제거하고, 앱 루트의 인증·프로필 상태만으로 메인 또는 프로필 설정 화면을 전환하도록 정리했다.

### 회원가입 프로필 설정

- 프로필 설정 1단계에 글래스형 뒤로가기 버튼을 추가했다.
- 1단계에서 뒤로가기를 누르면 Firebase 세션을 해제하고 로그인 화면으로 돌아간다.
- 2~4단계에 이전 단계로 돌아가는 글래스형 뒤로가기 버튼을 추가했다.
- 다음 단계는 오른쪽에서 진입하고, 뒤로가기는 이전 단계가 왼쪽에서 진입하는 역방향 슬라이드 애니메이션을 적용했다.
- 1단계에서 로그인 화면으로 돌아갈 때도 같은 방향의 부드러운 화면 전환을 적용했다.

### 네이버 로그인 버튼

- 제공받은 투명 배경 네이버 `N` PNG를 `NaverLoginMark` 에셋으로 교체했다.
- 기존 네이버 버튼의 초록 배경과 버튼 레이아웃은 유지했다.

## 영향 및 고려 사항

- 인증 SDK, OAuth 토큰 처리, 회원 프로필 저장 로직은 변경하지 않았다.

- 로딩 표시는 `AuthViewModel`과 `AppState`의 상태를 함께 사용해 화면 전환 사이의 빈 구간을 막는다.
