## 구현 요약

Realtime Database 규칙 누락으로 거부되던 위치 브로드캐스트를 복구했다. 활성 러너 데이터의 유효성·만료를 검증하고, 읽기·쓰기 실패를 빈 상태와 구분해 노출한다. 러닝 지도는 위치 갱신을 따라가며, 사용자가 지도를 직접 조작한 경우에만 추적을 중단하고 내 위치 버튼으로 재개한다.

## 변경 사항

- [x] Realtime Database 규칙 파일 및 Firebase 배포 설정 추가
- [x] 로그인 사용자의 활성 러너 읽기, 본인 UID 활성 러너 쓰기 허용
- [x] 위치 브로드캐스트·구독 취소 콜백 오류 처리
- [x] 위치 공유 오류의 반복 알림 방지
- [x] 좌표/갱신 시각 누락·2분 이상 stale 러너 제외
- [x] 주변 러너·친구 위치 조회 오류 상태 UI
- [x] 지도 드래그·확대/축소 시 자동 추적 중지
- [x] 러닝 중 내 위치 버튼 유지 및 자동 추적 재개
- [x] 활성 러너 만료 시간 단위 테스트 추가

## 운영 검증

운영 프로젝트 `pacing-a8639`에 Realtime Database 규칙 배포를 완료했다. 배포 후 현재 계정의 `activeRunners/{uid}`에 위도·경도 및 `updatedAt`이 정상적으로 기록됐고, 확인 시점 기준 7초 이내 최신 데이터임을 확인했다.

## 알려진 제한사항

- 전체 Xcode가 설치되지 않은 환경이라 iOS 빌드·XCTest 실행은 하지 못했다.
- 친구 핀과 1km 주변 목록의 최종 완료 판정은 최신 앱이 설치된 두 기기의 실기기 확인이 필요하다.
