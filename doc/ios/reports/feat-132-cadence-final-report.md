## 구현 요약

러닝 중 Core Motion 보행 센서 데이터를 이용해 케이던스를 누적 계산하고, 일시정지·재시작·종료 시점까지 동일한 기준으로 반영하도록 보정했다. 또한 음악 탭의 실제 하단 플레이어와 러닝 음악 시트의 이전·다음 곡 아이콘이 현재 색상 모드에 맞게 표시되도록 수정했다.

## 계산식 및 정확도 검토

케이던스는 다음 식으로 계산한다.

```text
평균 케이던스(SPM) = 누적 걸음 수 ÷ 활성 러닝 시간(초) × 60
```

- 첫 샘플의 누적 걸음 수를 버리지 않고 러닝 구간 시작 시각부터 포함한다.
- 일시정지 시간은 활성 시간에서 제외한다.
- 재시작할 때 새 구간 기준점을 만들고, 최종 평균은 각 구간의 걸음 수와 활성 시간을 합산해 계산한다.
- 센서 콜백이 늦게 도착해도 유효한 누적 걸음 수와 시간이라면 임의로 제외하지 않는다.
- 걸음 수가 감소하거나 시간 간격이 0 이하인 비정상 샘플은 제외한다.
- 비현실적인 센서 이상치가 화면을 오염시키지 않도록 300 SPM을 상한으로 둔다.
- 종료 직전 누락될 수 있는 꼬리 데이터를 `queryPedometerData`로 다시 조회한 후 최종값을 확정한다.

고도는 이번 브랜치에서 계산식을 변경하지 않았다. 기존 구현은 `CLLocation.altitude`와 `verticalAccuracy`를 사용하며, 수직 정확도가 허용 범위 안이고 일정 임계값 이상의 상승만 누적한다. GPS 고도 자체의 측정 오차를 완전히 제거할 수 없으므로 실제 기기 검증에서 추가 확인이 필요하다.

## 알려진 제한사항

- Core Motion의 센서값 자체가 제공되지 않는 경우 케이던스는 확정할 수 없으며 UI에서는 `--` 상태를 유지한다.
- 케이던스는 실제 발걸음 감지 품질, 휴대폰 위치, Apple Watch 데이터 제공 여부에 영향을 받는다. 이 코드는 계산식과 lifecycle 누락을 보정하지만 센서 오차 자체를 0으로 만들 수는 없다.
- 고도는 기존 GPS 기반 구현을 유지했으며, 수직 정확도 오차 검증은 실제 기기에서 별도로 필요하다.
- 기존 프로젝트의 Apple Music 추천 서비스 경고(`startIndex` 미사용)는 이번 작업 범위와 무관해 수정하지 않았다.
