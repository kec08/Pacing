# fix #158 러닝 고도 상승 GPS 드리프트 과대 집계 보정 최종 개발 보고서

> **완료일**: 2026-09-18
> **관련 이슈**: [#158](https://github.com/kec08/Pacing/issues/158)
> **브랜치**: `fix/158-elevation-gain-barometer-calibration`
> **테스트 상태**: 개발자 실기기 테스트 완료

## 구현 요약

평지성 7.5km 러닝에서 GPS 절대 고도 드리프트가 반복 저점·정점으로 해석되어 고도 상승이 152m까지 과대 집계되던 문제를 보정했습니다. 기압계가 지원되는 기기에서는 `CMAltimeter`의 상대 고도를 우선 사용하고, 미지원 기기에서만 더 보수적인 GPS fallback 정책을 적용합니다.

## 변경 사항

- `ElevationRepository` 추상화와 `CoreMotionElevationRepository`를 추가했습니다.
- 러닝 시작 시 기압계 상대 고도를 수집하고, pause/resume 시 기준점을 보존하여 재개 직후 점프를 제외합니다.
- `ElevationGainCalculator`에 중앙값 평활화·상승/하강 히스테리시스를 적용했습니다.
  - 확정 상승 최소 폭: 3m
  - 새 기준점 확정 하강 폭: 2m
- 러닝 중, 종료 시점의 고도 상승 계산을 동일한 기압계 입력으로 통일했습니다.
- 기압계 미지원 기기에서는 GPS 수직 정확도 3m 이하, 확정 상승 20m, 하강 15m, 거리당 최대 10m의 보수적 fallback을 사용합니다.
- 합성 GPS 드리프트·실제 상승·작은 압력 노이즈 회귀 테스트를 추가했습니다.

## 검증 결과

| 항목 | 결과 |
|---|---|
| 7.5km 반복 GPS 드리프트 재현 | 기존 GPS 계산은 140m 초과, 기압계 계산은 12m로 검증 |
| 실제 분리 상승 구간 | 15m 상승 3회가 45m로 누적됨 |
| 작은 압력 노이즈 | 0m로 처리되어 누적되지 않음 |
| pause/resume | 기압계 상대 기준점과 누적 고도를 유지하도록 구현 |
| `PacingTests` | ✅ iOS 26.0 iPhone 16 Simulator 통과 |
| 실기기 테스트 | 개발자 확인 완료 |

## 기술적 고려 사항

- `CLLocation.altitude`는 수직 드리프트에 취약하므로 지원 기기에서 고도 상승의 주 입력으로 사용하지 않습니다.
- 기압계 상대 고도는 세션별 절대 해발고도 대신 변화량만 필요로 하는 고도 상승 계산에 적합합니다.
- 입력 소스가 부족할 때는 임의의 `0m` 값을 확정하지 않고 기존 미측정 표시 정책을 유지합니다.

## 알려진 제한사항 및 후속 작업

- 기압계가 지원되지 않는 기기에서는 보수적인 GPS fallback을 사용하므로 완만한 실제 오르막이 일부 누락될 수 있습니다.
- 동일 경로에서 Nike Run 등 외부 앱과 비교하는 장거리 반복 실기기 QA를 추가로 축적해야 합니다.
- 고도 입력 소스·유효 샘플 수·확정 상승 구간을 사용자용 진단 화면에 노출하는 기능은 후속 범위입니다.

> **개발자 검토 의견**: GPS 드리프트로 인한 비정상적인 고도 상승 누적을 차단했고, 지원 기기에서는 기압계 기반 변화량으로 측정 정책을 전환했습니다.
