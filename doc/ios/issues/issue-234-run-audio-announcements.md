# [fix] 10km 마지막 구간 페이스와 러닝 TTS·음악 복구

> **상태**: 수정 완료, 실기기 QA 통과
> **작성일**: 2026-11-24
> **이슈**: [#234](https://github.com/kec08/Pacing/issues/234)
> **브랜치**: `feat/234-run-audio-announcements`

## 증상

- 정확히 10.00km에서 종료하면 활동 상세의 구간별 페이스에 10km 구간이 빠졌다.
- 러닝 종료 후 최종 결산 음성이 약 10초, 길게는 30초 늦게 나왔다.
- 거리·페이스 숫자를 읽는 속도가 빨랐다.
- 안내 음성 뒤 음악이 끊기거나 작아진 채로 남았다.
- 결산 합성이 늦으면 시스템 음성(기계음)으로 대신 읽었다.
- 실기기 Debug 빌드에서 `onnxruntime.framework` 수정 단계가 `PlistBuddy`/`codesign` sandbox 오류로 실패했다.

## 원인

| 증상 | 원인 |
| --- | --- |
| 10km 구간 누락 | 화면은 `%.2f`로 10.00km를 표시하지만, 실제 거리 9.996km처럼 경계 직전 값으로 마지막 구간을 계산했다. |
| 결산 지연 | 1. 마지막 구간 랩 안내 합성이 MeloTTS 직렬 큐에서 결산보다 앞에 있었다. 2. Watch 최종 수치를 최대 3초 기다린 뒤에야 결산을 요청했다. 3. 결산 전체 문장 합성이 음성 길이보다 오래 걸렸다(시뮬레이터 14~15초). |
| 합성 자체가 느림 | 번들 모델의 합성곱 249개와 행렬곱 5개가 모두 동적 INT8(`ConvInteger`/`MatMulInteger`)이었고, ONNX Runtime CPU에서 이 연산이 느렸다. 스레드 수를 바꿔도 개선되지 않았다(2/4/6개: 23.6/16.6/14.8초). |
| 기계음 | 합성 제한 시간을 넘기면 `AVSpeechSynthesizer`로 대체했다. |
| 음악 복구 실패 | 안내 후 오디오 세션을 원래 설정으로 되돌리지 않았다. |
| Debug sandbox 오류 | Release 아카이브용 프레임워크 `Info.plist` 수정과 재서명을 Debug 빌드에서도 실행했다. |

## 해결

- 마지막 구간을 화면·저장·음성과 같은 `%.2f` 거리로 확정한다.
- 종료 처리 중에는 랩 안내를 내지 않고, 대기 중인 합성을 취소한다.
- 일시정지 시점에 결산을 미리 합성하고, 종료하면 Watch 대기 없이 바로 재생한다. Watch 수치가 바뀌면 재생 전에만 새 수치로 교체한다.
- 결산 문구는 끊김 없이 한 문장으로 합성한다. 시스템 음성으로는 대체하지 않는다.
- INT8 모델을 부동소수 Conv/MatMul로 변환했다. 가중치는 FP16으로 저장해 앱에 넣는다. 결산 합성이 14.5초에서 2.2초로 줄었다.
- 새 모델이 약 10% 빨리 읽어 길이 보정 1.1배를 적용했고, 거리·페이스 문구는 `lengthScale` 1.16으로 천천히 읽는다.
- 안내 중에는 `.duckOthers`로 음악만 줄이고, 안내가 끝나면 이전 오디오 세션 설정을 복원한다.
- ONNX 수정 스크립트는 Release에서만 실행한다.
