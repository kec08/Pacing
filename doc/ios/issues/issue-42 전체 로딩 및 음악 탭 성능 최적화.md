# [feat] 전체 로딩 및 음악 탭 성능 최적화

> **이슈 번호**: #42
> **유형**: feature
> **작성일**: 2026-07-15
> **상태**: Open

## 개요

앱 전반의 로딩 체감을 개선하고, 특히 노래 탭 진입 시 과도한 재로딩을 줄입니다.

- 노래 탭 초기 로딩과 재진입 로딩 분리
- 최근에 들은 앨범만 재진입 시 최신 기준으로 갱신
- 추천/친구 플레이리스트/장르/무드 섹션은 캐시 우선으로 유지
- 내 플레이리스트 동기화는 자동 진입 로딩에서 제외

## 사용자 문제

- 노래 탭에 들어갈 때마다 전체 로딩이 다시 도는 느낌이 강함
- 최근에 들은 음악은 최신으로 보고 싶지만, 나머지 추천 데이터까지 매번 같이 다시 불러와 UX가 느려짐
- 탭 이동만으로도 불필요한 네트워크 호출이 발생해 체감 성능이 떨어짐

## 작업 범위

1. `SongView` 진입 트리거를 초기 진입과 재진입으로 분리
2. `SongViewModel`에서 최근 앨범 갱신 로직과 추천성 데이터 로드를 분리
3. 노래 탭 자동 진입 시 `syncCurrentUserPlaylists()` 실행 제거
4. 당겨서 새로고침 시에만 전체 데이터 강제 갱신 유지
5. 기존 로딩/빈 상태/권한 상태 흐름 회귀 여부 점검

## 완료 기준

- [ ] 노래 탭 첫 진입 시 필요한 데이터가 정상 표시된다
- [ ] 노래 탭 재진입 시 전체 섹션이 다시 로딩되지 않는다
- [ ] 최근에 들은 앨범만 탭 재진입 시 최신 재생 이력 기준으로 갱신된다
- [ ] 추천/친구 플레이리스트/장르/무드 섹션은 캐시된 데이터를 우선 유지한다
- [ ] 내 플레이리스트 동기화는 수동 액션으로만 실행된다
- [ ] 당겨서 새로고침 시 전체 갱신이 정상 동작한다

## 구현 메모

- 수정 중심 파일:
  - `SongView.swift`
  - `SongViewModel.swift`
- 실시간 반영 대상은 `최근에 들은 앨범`만 유지
- 추천성 데이터는 초기 로드 또는 명시적 새로고침 시 갱신
